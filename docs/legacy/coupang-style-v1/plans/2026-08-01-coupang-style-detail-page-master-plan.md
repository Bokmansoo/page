# 쿠팡형 AI 상세페이지 생성 전체 기획

> 상태: 이전 버전 참고 문서  
> 2026-08-01 인터뷰에서 확정한 범용 상품 수집, 공급처 자산 참고 전용 정책, AI 리디자인, 소셜 로그인, 크레딧·결제까지 포함한 최종 기준은 [Sellform Commerce Studio V2 최종 기획서](../../../superpowers/plans/2026-08-01-sellform-commerce-studio-v2-final-master-plan.md)를 따른다.

## 1. 목표

판매자가 상품 링크·상품 정보·상세 이미지 묶음을 넣으면, 단순 수치 카드 페이지가 아니라 구매자가 위에서 아래로 읽으며 제품을 이해하고 구매를 판단할 수 있는 **모바일 세로형 판매 상세페이지**를 만든다.

목표 결과는 다음 흐름을 따른다.

1. 불편/필요성 제시
2. 제품을 크게 보여주는 HERO
3. 핵심 기능별 설명과 서로 다른 제품 이미지
4. 사용 상황·구성품·디테일 설명
5. 근거 있는 수치/스펙 표
6. 구매 전 확인과 CTA

## 2. 핵심 원칙

- 원본 상품 이미지와 상품 사실을 우선한다. AI가 제품 형태·로고·사양을 지어내지 않는다.
- 하나의 상품 사진을 여러 섹션에 반복 배치하지 않는다.
- 상세 이미지가 충분하면 이미지 중심, 부족하면 HTML 정보 그래픽, 둘 다 부족하면 판매자 보완 요청을 사용한다.
- 숫자·성능·구성품·인증 등 판매 주장은 확인된 상품 사실과 연결한다.
- 생성 전에 스토리보드를 보여주고, 판매자가 이미지/섹션을 바꿀 수 있게 한다.
- 편집 화면과 JPG/PNG 출력은 같은 렌더러를 사용한다.

## 3. 입력과 산출물

| 구분 | 입력 | 처리 | 산출물 |
| --- | --- | --- | --- |
| 기본 정보 | 상품명, 카테고리, 가격, 판매 포인트 | 사실 후보 정리 | 상품 요약 |
| 이미지 묶음 | 대표컷, 기능컷, 구성품, 사용 장면, 스펙 이미지 | OCR·품질·역할 분류 | 이미지 자산 보드 |
| 링크 | 상품/참고 링크 | 허용된 범위의 제목·텍스트·이미지 수집 시도 | 출처 기록 및 보조 사실 |
| 판매자 확인 | 자동 분류/사실/스토리보드 수정 | 확인 상태 저장 | 생성 승인 |
| 최종 출력 | 웹 미리보기, JPG, PNG | 공통 렌더링 | 업로드 가능한 상세페이지 |

## 4. 목표 템플릿: `commerce_story`

기본 템플릿은 상품 자료에 따라 6~10개 섹션을 조립한다. 모든 칸을 억지로 채우지 않는다.

| 우선순위 | 섹션 | 필요한 자료 | 대체 규칙 |
| --- | --- | --- | --- |
| 필수 | 문제/공감 | 판매자 설명 또는 확인된 사실 | 짧은 텍스트 블록 |
| 필수 | HERO | 대표 제품컷 | 안전한 HTML HERO + 사진 업로드 요청 |
| 권장 | 핵심 기능 1~3 | 기능 이미지 또는 확인된 기능 사실 | 수치/비교 그래픽 |
| 권장 | 사용 장면 | 사용 이미지 | 단계 안내 그래픽 |
| 조건부 | 구성품/디테일 | 구성품·확대 이미지 | 확인된 구성품 표 |
| 필수 | 스펙 | 확인된 숫자·단위 | 스펙 표 |
| 필수 | CTA/구매 전 확인 | 가격·배송·주의사항 | 확인 체크리스트 |

## 5. 성공 기준

- 기준 상품 3종에서 HERO를 포함한 6개 이상 섹션을 생성한다. 단, 자료 부족 시에는 근거 없는 섹션보다 명확한 보완 요청을 우선한다.
- 본문에서 동일 `asset_id`가 HERO 외 1회보다 많이 반복되지 않는다.
- 확인된 사실이 없는 수치/성능 주장은 출력하지 않는다.
- 판매자가 이미지 역할과 스토리보드를 2회 이하의 교체로 수정할 수 있다.
- 미리보기와 JPG/PNG의 섹션 순서·문구·이미지가 일치한다.

## 6. 범위 밖

- 쿠팡 페이지를 우회해 제한된 상세 이미지를 무단 수집하는 기능
- 근거 없는 효능·성능 문구 생성
- AI가 원본에 없는 제품 구조나 로고를 새로 만들어 사실처럼 사용하는 기능
- 모든 상품에 이미지 생성 API를 강제 사용하는 기능

## 7. Sprint 순서

| Sprint | 이름 | 핵심 결과 |
| --- | --- | --- |
| 0 | 기준선 및 품질 기준 | 기준 상품/참고 상세페이지/평가표 고정 |
| 1 | 상품 자료 묶음 입력 | 다중 이미지와 상세 정보 입력 흐름 |
| 2 | 자산 분류·품질·OCR | 이미지 역할과 사용 가능 여부 |
| 3 | 사실 보드와 증거 연결 | 검증된 스펙/기능/구성품 데이터 |
| 4 | 스토리보드 플래너 | 이미지·사실을 섹션 흐름으로 배치 |

| 6 | 판매자 검수·편집 | 이미지 교체·섹션 순서·문구 수정 |
| 7 | 출력 일치·업로드 준비 | JPG/PNG와 미리보기 일치 |
| 8 | 기준 상품 품질 검증·선택적 AI 보강 | 출시 판정과 제한적 이미지 보강 실험 |

## 8. 의사결정 기준

Sprint 4가 끝났을 때 이미지 묶음에서 HERO/기능/구성품/스펙으로 최소 4개의 역할을 안정적으로 구분하지 못하면 Sprint 5를 시작하지 않는다. 먼저 분류·판매자 확인 UX를 보강한다.
