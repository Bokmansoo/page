# Sellform V2 Sprint UX-2E-0: API 연결 준비형 생성 파이프라인

상태: 구현 완료 · API 연결 대기  
선행: UX-2D-1 안전한 자동 이미지 배치  
후속: UX-2E LLM 텍스트·OCR·이미지 생성 API 연결

## 1. 목적

현재 Mock은 판매자 사진·확정 사실을 안전하게 조립할 수 있지만, 링크와 사진만으로 제품 특징을 해석하거나 사람 사용 장면을 새로 생성할 수는 없다. 이 Sprint는 외부 API를 호출하지 않고도 실제 AI 생성에 필요한 입력·승인·출력 계약을 먼저 만든다.

API 키와 크레딧이 준비되면 화면과 데이터 구조를 다시 설계하지 않고, 이 Sprint에서 저장한 장면 계획을 LLM·OCR·이미지 생성 작업으로 실행하는 것이 목표다.

## 2. 사용자 결과

판매자는 사진·링크·상품 정보를 입력한 뒤, 상세페이지가 어떤 장면과 문구로 만들어질지 먼저 확인한다.

```text
사진·링크·상품 정보 입력
  → 상품 브리프 확인
  → AI 생성 장면 계획 확인
  → 지금: 안전한 원본 사진/정보형으로 Mock 미리보기
  → 나중: 장면별 LLM 카피·이미지 생성 실행
  → 판매자 검수·다운로드
```

예를 들어 마사지기라면 `대표 제품 컷`, `목·어깨 사용 장면`, `충전 또는 전원 안내`, `온열·기능 강조`, `제품 크기`, `사양·주의사항`을 장면으로 계획한다. 사람 사용 장면이나 한국어로 재구성한 사양 그래픽은 API 연결 전에는 **생성 대기**로 표시하며, 가짜 이미지로 채우지 않는다.

## 3. 범위

### 3.1 상품 브리프(Product Brief)

프로젝트마다 아래 구조화 데이터를 만들고 수정·저장한다.

- 제품명, 카테고리, 모델·옵션·색상, 판매 채널
- 확정 사실 카드: 규격·전원·구성품·사용 시간·주의사항과 근거 ID
- 판매자가 제공한 제품 설명과 금지 표현
- 대표 기준 사진 ID, 제품 정체성 기준(색상·형태·버튼·포트·구성품)
- 링크 출처와 사용 상태: `reference_only`, 직접 입력, 판매자 보유 자료
- 미확인 정보와 판매자 확인 필요 항목

브리프는 LLM이 임의로 채우지 않는다. API 연결 전에는 기존 사실 카드와 판매자 입력에서만 만든다.

### 3.2 장면 계획(Scene Plan)

상세페이지 각 섹션에 아래 데이터를 저장한다.

- `scene_type`: `hero_product`, `usage_scene`, `feature_closeup`, `charging_or_power`, `comparison`, `spec_graphic`, `notice`
- 목표: 구매 흐름에서 이 장면이 답하는 질문
- 사용할 확정 사실 ID와 허용된 기준 사진 ID
- 필요한 결과 유형: `existing_photo`, `html_information`, `generated_image`, `generated_copy`
- Mock 상태: `ready_with_existing_asset`, `information_fallback`, `generation_pending`, `needs_seller_input`
- 이미지 생성 프롬프트 청사진과 금지 요소(외국어 문구, 가격, 로고, 타사 제품, 제품 형태 변경)
- LLM 문구 청사진: 헤드라인 목적, 본문 길이, 허용 사실, 금지 표현
- 판매자 승인 상태와 재생성 이력

`comparison`은 경쟁 상품의 우월성을 자동 주장하지 않는다. 판매자가 입력·확인한 비교 기준이 있을 때만 계획하며, 그렇지 않으면 구매 전 확인 포인트 또는 자사 제품 사양 안내로 대체한다.

### 3.3 API 중립 작업 계약

실제 공급자를 고정하지 않는 `GenerationJob` 요청·결과 계약을 만든다.

- 입력: 프로젝트·버전·장면 ID, 승인된 브리프, 기준 사진, 프롬프트 청사진, 출력 규격
- 상태: `draft`, `pending_provider`, `running`, `needs_seller_review`, `succeeded`, `failed`, `cancelled`
- 결과: 생성 텍스트/이미지, 제공자 작업 ID, 비용·크레딧 예상 및 실제값, 정체성·OCR·권리 검사 결과
- 실패: 공급자 오류·안전 차단·제품 정체성 불일치·판매자 거절을 구분하고 재시도 가능한 사유를 제공

API 키와 원본 이미지 URL은 브라우저에 노출하지 않는다. 제공자 선택, 요청, 비용 차감, 결과 저장은 백엔드 어댑터가 담당한다.

### 3.4 Mock 동작 원칙

- 외부 LLM·OCR·이미지 생성 API를 호출하지 않으며 비용도 발생하지 않는다.
- `existing_photo`는 UX-2D-1 안전 게이트를 통과한 판매자 보유 사진만 쓴다.
- `html_information`은 확정 사실 기반 한국어 카드·사양표로 렌더링한다.
- `generated_image`와 `generated_copy`는 생성 대기 카드와 장면 목적·필요 기준 사진을 표시한다.
- Mock은 사람 사용 장면, 한국어로 바뀐 중국어 사양 이미지, 비교 우월 문구를 만들어 낸 것처럼 표시하지 않는다.

### 3.5 결과 화면과 고급 편집

- 기본 결과 화면에는 `상품 브리프`, `생성 예정 장면 N개`, `현재 안전한 원본 사진 N개`, `판매자 확인 필요 N개`를 요약한다.
- 장면 카드마다 기준 사진, 사용 사실, 예상 문구, 생성 필요 여부를 확인·수정할 수 있다.
- 위험·중복 사진은 장면 기준 사진으로 자동 선택하지 않는다. 수동 사용은 UX-2D-1의 별도 확인을 유지한다.
- 생성 대기 장면은 기존 HTML 정보형 또는 안전한 원본 사진으로 미리보기에 표시하고, 최종 출력에 빈 이미지·가짜 이미지를 넣지 않는다.

## 4. 구현 작업

### 4.1 백엔드

1. `ProductBrief`와 `ScenePlan` 저장 모델 또는 버전 스냅샷 구조를 정의한다.
2. 기존 상품 입력·사실 카드·자산 검사 결과에서 브리프 초안을 만드는 규칙 기반 서비스와 API를 만든다.
3. 카테고리·확정 사실·안전 자산을 기준으로 기본 장면 계획을 생성한다.
4. 제공자 중립 `GenerationJob` 요청/상태 스키마와 어댑터 인터페이스를 만든다. 이 Sprint에서는 실제 제공자 호출 구현을 넣지 않는다.
5. 장면 계획·브리프·판매자 승인 상태를 `DetailPageVersion` 스냅샷에 포함한다.
6. 결과물 렌더러는 생성 대기 상태를 안전한 정보형으로 처리하며, API 미연결 상태에서 생성 완료로 표시하지 않는다.

### 4.2 프런트엔드

1. 입력 완료 뒤 상품 브리프 검토 카드와 누락·충돌 경고를 표시한다.
2. HERO부터 사양·필수 고지까지 장면 계획 목록을 보여 준다.
3. 장면별 기준 사진·확정 사실·생성 대기 이유를 확인하고 수정하는 고급 편집 UI를 만든다.
4. API 미연결 상태는 `AI 생성 연결 준비 중`으로 명확히 표시하며, 생성 버튼·비용 표시를 가짜로 제공하지 않는다.
5. 생성 대기 장면이 있는 다운로드는 기존 안전한 미리보기 출력임을 표시하고, 실제 AI 생성본과 혼동되지 않게 한다.

### 4.3 테스트

- 마사지기 기준 상품의 브리프에 모델·전원·크기·배터리·사용 시간이 사실 근거와 함께 저장되는지 검증한다.
- 안전한 제품 사진, 외국어 사양 사진, 사용 장면 참고 사진을 섞었을 때 기준 사진 선택이 UX-2D-1 규칙을 따르는지 검증한다.
- API 미연결 상태에서 `generated_image` 장면이 가짜 완성 이미지나 과장 카피로 바뀌지 않는지 검증한다.
- 장면 계획, 브리프, 승인 상태가 생성본·최종본·JPG·분할 ZIP에 같은 버전 스냅샷으로 유지되는지 검증한다.
- 링크가 차단되어도 판매자 직접 입력·사진으로 브리프와 장면 계획을 계속 만들 수 있는지 검증한다.

## 5. 완료 조건

- API 비용 없이 상품 브리프와 장면 계획을 생성·수정·버전 저장할 수 있다.
- 모든 생성 예정 문구·이미지는 근거 사실과 기준 사진을 가진다.
- 사람 사용 장면·충전 장면·한국어 사양 그래픽처럼 API가 필요한 요소는 `생성 대기`로 명확히 구분된다.
- 위험 OCR·공급처·중복 이미지는 생성 기준 사진으로 자동 선택되지 않는다.
- 비교 섹션은 확인된 비교 사실이 없으면 우월성 주장을 하지 않는다.
- 실제 API 연결 전에는 키·비용·외부 호출이 발생하지 않는다.
