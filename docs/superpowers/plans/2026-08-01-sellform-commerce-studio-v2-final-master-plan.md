# Sellform Commerce Studio V2 최종 기획서

작성일: 2026-08-01  
상태: **최종 제품 방향 및 구현 기준**  
문서 역할: 이 문서는 상품 수집, 사실 확인, AI 이미지·상세페이지 생성, 편집, 채널별 출력, 로그인, 크레딧과 결제까지 포함하는 Sellform V2의 단일 기준 문서다.

---

## 1. 제품 비전

Sellform은 1688·타오바오·샤오홍슈·쿠팡·네이버 스마트스토어·국내 도매몰 또는 직접 촬영한 상품 자료를 바탕으로, 1인 셀러가 쿠팡과 스마트스토어에서 사용할 수 있는 한국형 판매 상세페이지를 만드는 AI 커머스 스튜디오다.

판매자는 상품 링크와 최소한의 사진·정보만 준비한다. Sellform은 자료를 수집하고, 중국어를 번역하고, 사실과 이미지를 정리하며, 구매 흐름에 맞는 스토리보드와 새로운 시각 자료를 추천한다. 판매자는 자동 결과를 간단히 확인·수정한 뒤 채널별 결과물을 내려받는다.

최종 목표는 공급처 상세페이지를 복제하는 것이 아니다. 상품의 사실과 외형을 근거로 **새로운 한국형 상세페이지를 기획·리디자인**하는 것이다.

## 2. 핵심 고객

### 2.1 1차 고객

- 혼자 쿠팡그로스 또는 쿠팡 마켓플레이스를 운영하는 셀러
- 네이버 스마트스토어를 운영하는 1인 셀러
- 1688·타오바오 등 해외 도매 사이트에서 상품을 소싱하는 셀러
- 국내 도매 사이트에서 상품을 소싱하는 셀러
- 직접 촬영한 자체 상품을 판매하는 소규모 브랜드

### 2.2 해결하려는 문제

- 공급처 페이지가 중국어이거나 접근이 차단되어 상품 정보를 정리하기 어렵다.
- 사진과 스펙은 있지만 판매 흐름과 디자인을 만들기 어렵다.
- 원본 디자인을 그대로 사용할 경우 저작권·상표·차별화 문제가 발생할 수 있다.
- 쿠팡과 스마트스토어 규격에 맞게 다시 나누고 저장하는 과정이 번거롭다.
- 디자인 도구를 배우거나 외주를 맡기기에는 비용과 시간이 많이 든다.

## 3. 제품 원칙

1. **사실 우선**: 확인되지 않은 수치·성능·구성품·효능을 만들지 않는다.
2. **상품 정체성 보존**: AI가 상품 형태, 조작부, 구성품, 로고를 임의로 바꾸지 않는다.
3. **원본 디자인 미복제**: 공급처 이미지의 레이아웃·카피·장식을 그대로 복제하지 않는다.
4. **참고 자료와 최종 자산 분리**: 공급처 이미지는 기본적으로 `reference_only`이며 최종 출력 자산과 구분한다.
5. **판매자 승인**: 충돌하거나 불확실한 정보는 자동 확정하지 않고 판매자가 승인한다.
6. **자동 추천 + 간단한 수정**: 처음부터 빈 캔버스를 주지 않고 AI 초안을 먼저 제공한다.
7. **템플릿 기반 변형**: 검증된 판매 구조 안에서 상품과 브랜드에 맞춰 변형한다.
8. **스펙은 마지막**: 상세한 상품 스펙과 구매 전 확인 정보는 최종 상세페이지의 마지막 섹션에 고정한다.
9. **채널 독립 마스터**: 하나의 프로젝트에서 마스터 디자인을 만들고 채널별 규격으로 변환한다.
10. **실패도 정상 흐름**: 링크 수집, OCR, AI 생성, 출력 실패 시 원인과 다음 행동을 제공한다.

## 4. 지원 상품 입력 경로

### 4.1 해외 소싱 상품

- 1688, 타오바오, 티몰, 알리익스프레스, 샤오홍슈 및 유사 해외 판매 사이트
- 상품 URL, 대표 이미지, 기능 이미지, 스펙 이미지, 구성품 이미지
- 중국어 OCR 및 한국어 번역
- 모델·옵션·포장 단위·본체 단위 구분

### 4.2 국내 소싱 상품

- 쿠팡, 스마트스토어, 국내 도매몰 및 유사 판매 사이트
- 상품 URL과 판매자가 접근 가능한 페이지 자료
- 자동 수집 실패 시 브라우저 보조 수집 또는 직접 업로드

### 4.3 자체 상품

- 직접 촬영 사진
- 판매자가 입력한 상품명, 카테고리, 기능, 구성품, 스펙, 주의사항
- 브랜드 로고, 색상, 폰트 등 브랜드 키트

## 5. 링크 수집과 브라우저 확장 프로그램

### 5.1 일반 수집

서버는 허용된 범위에서 공개 페이지의 제목·본문·이미지·메타데이터 수집을 시도한다. 접근 차단, 로그인, 캡차 또는 동적 렌더링으로 실패하면 강제로 우회하지 않는다.

### 5.2 `현재 상품 가져오기`

판매자가 자신의 브라우저에서 상품 페이지를 정상적으로 열고 확장 프로그램의 `현재 상품 가져오기`를 누르면 다음 자료를 수집 후보로 보낸다.

- 현재 URL과 페이지 제목
- 사용자가 화면에서 확인 가능한 상품명·옵션·스펙 텍스트
- 선택한 상품 이미지와 이미지 순서
- 사용자가 선택한 상세 설명 영역 또는 스크린샷
- 출처 사이트, 수집 시각, 언어

확장 프로그램은 캡차나 접근 제어를 우회하지 않는다. 사용자가 접근 가능한 페이지에서 명시적으로 선택한 자료만 전송하며, 전송 전 미리보기와 제외 기능을 제공한다.

### 5.3 확장 프로그램 인증

- 브라우저 로그인 쿠키를 복사하지 않는다.
- 웹 서비스에서 발급한 짧은 수명의 일회성 연결 코드로 확장 프로그램을 연결한다.
- 연결 토큰은 사용자·워크스페이스·허용 범위와 만료 시간을 가진다.
- 연결 해제와 모든 기기 로그아웃을 지원한다.

## 6. 최소 입력과 권장 입력

### 6.1 최소 입력

- 상품명 또는 상품 URL
- 상품을 식별할 수 있는 대표 사진 1장
- 판매자가 확실히 아는 핵심 정보 1개 이상

최소 입력만으로도 분석은 시작할 수 있지만, 자료 부족 상태를 명확히 표시하고 근거 없는 결과를 만들지 않는다.

### 6.2 권장 입력

- 대표 제품컷 1~3장
- 정면·측면·후면 사진
- 조작부 또는 기능 확대 사진
- 실제 사용 장면
- 구성품 사진
- 소재·제형·디테일 사진
- 스펙표 또는 설명서 사진
- 상품명, 카테고리, 주요 고객, 핵심 장점, 구성품, 주의사항

## 7. 자료와 사실 처리 모델

### 7.1 자산 상태

| 상태 | 의미 | 최종 출력 사용 |
| --- | --- | --- |
| `reference_only` | 공급처 디자인·스펙·사용 장면 참고 자료 | 기본 금지 |
| `seller_owned` | 판매자가 직접 촬영하거나 사용 권한을 확인한 자산 | 가능 |
| `ai_generated` | 승인된 상품 근거로 생성된 신규 자산 | 승인 후 가능 |
| `derived_graphic` | 확인된 사실로 만든 차트·아이콘·스펙 그래픽 | 가능 |
| `blocked` | 저작권·로고·품질·사실 문제로 사용 금지 | 금지 |

### 7.2 사실 상태

| 상태 | 의미 |
| --- | --- |
| `extracted` | OCR·링크·이미지에서 추출한 후보 |
| `source_confirmed` | 하나 이상의 출처에서 확인됨 |
| `seller_confirmed` | 판매자가 최종 확인함 |
| `needs_review` | 표현·단위·성능을 추가 확인해야 함 |
| `conflicted` | 서로 다른 출처가 다른 값을 제공함 |
| `rejected` | 사용하지 않기로 결정함 |

### 7.3 사실 카드

각 사실은 다음을 보존한다.

- 원문과 번역문
- 정규화한 값과 단위
- 출처 URL 또는 이미지 좌표
- 모델·옵션·포장 단위·본체 단위
- 신뢰도
- 판매자 수정과 승인 이력
- 상세페이지에서 사용된 섹션

## 8. 이미지 이해와 분류

AI는 사진마다 다음을 분류한다.

- 대표 제품컷
- 기능컷
- 사용 장면
- 구성품
- 소재·디테일
- 스펙표
- 포장·배송 정보
- 배너·장식·로고 중심 이미지
- 중복 또는 저화질 이미지

한 이미지가 여러 역할을 가질 수 있지만 최종 상세페이지에서 같은 이미지를 반복적으로 사용하지 않는다. 텍스트가 과도하게 포함된 공급처 배너는 OCR 근거로만 사용하고 최종 시각 자산에서는 제외한다.

## 9. AI 리디자인과 이미지 생성

### 9.1 기본 방식

Sellform은 `템플릿 기반 AI 변형`을 기본 방식으로 사용한다.

1. 상품과 자료를 분석한다.
2. 필요한 이미지 장면을 자동 추천한다.
3. 판매자가 장면과 표현을 간단히 수정한다.
4. 상품 정체성을 고정한 상태로 신규 장면을 생성한다.
5. 승인된 결과만 상세페이지에 사용한다.

### 9.2 추천 장면 예시

- 제품 단독 HERO
- 사람이 상품을 사용하는 장면
- 충전 또는 보관 장면
- 조작 방법
- 핵심 기능 시각화
- 소재·제형·구조 확대
- 구성품 배열
- 크기·규격 비교

### 9.3 생성 안전장치

- 상품 외형을 확인할 기준 이미지가 부족하면 생성하지 않고 보완을 요청한다.
- 제품에 없는 버튼, 포트, 구성품, 인증 마크를 생성하지 않는다.
- 원본 공급처 디자인과 카피를 재현하지 않는다.
- 생성 결과는 상품 유사도와 사실 일치 검사를 통과해야 한다.
- 얼굴·손·신체 접촉 장면은 왜곡과 부자연스러운 사용법을 검사한다.
- 의료·치료·효능 보장 표현은 자동 차단하거나 순화한다.

## 10. 상세페이지 스토리 구조

상품 자료에 따라 7~12개 섹션을 조립한다. 자료가 없으면 빈 섹션을 억지로 만들지 않는다.

1. 문제 또는 사용 상황 공감
2. 제품 정체성을 보여주는 HERO
3. 핵심 구매 이유 요약
4. 핵심 기능 1
5. 핵심 기능 2
6. 핵심 기능 3
7. 사용 장면 또는 사용 방법
8. 소재·구조·디테일
9. 구성품 또는 크기 안내
10. 신뢰·주의·구매 전 확인
11. CTA
12. **최종 제품 스펙 및 고지 정보**

스펙 섹션은 항상 마지막에 배치하며, 확인된 사실만 사용한다. 상품에 필요한 인증·주의·법정 고지 항목이 있다면 스펙과 함께 마지막 영역에 배치한다.

## 11. 자동 추천과 편집 방식

### 11.1 기본 경험

- AI가 템플릿, 색상, 섹션, 카피, 이미지 장면을 추천한다.
- 판매자는 결과를 먼저 본 뒤 필요한 부분만 수정한다.
- 선택 가능한 추천안은 지나치게 많게 만들지 않고 2~3개로 제한한다.

### 11.2 블록 편집기

- 섹션 순서 변경
- 이미지 교체 또는 재생성
- 문구 직접 수정 또는 AI 수정
- 섹션 숨김·복원
- 색상·폰트·간격 조정
- 사실 카드와 문구 근거 확인
- 변경 전후 비교와 버전 복원

자유 배치 캔버스는 후속 기능이며, 초기 제품은 블록 편집기로 제한한다.

## 12. 브랜드 키트

- 브랜드명과 로고
- 주·보조 색상
- 선호 폰트와 말투
- 금지 표현
- 기본 CTA 문구
- 워터마크 또는 저작권 표기

브랜드 키트는 워크스페이스에 저장하고 프로젝트마다 재사용할 수 있다.

## 13. 채널별 결과물

한 프로젝트에서 공통 마스터를 만들고 다음 버전을 함께 제공한다.

- 쿠팡용 긴 이미지 및 자동 분할 JPG/PNG
- 스마트스토어용 긴 이미지 및 자동 분할 JPG/PNG
- 웹 미리보기
- 섹션별 이미지 묶음
- 같은 버전의 재다운로드

채널 규격은 코드에 임의로 고정하지 않고 버전이 있는 프리셋으로 관리한다. 미리보기, 긴 이미지, 분할 이미지는 동일한 렌더러와 최종 스냅샷을 사용해야 한다.

## 14. 로그인·회원·워크스페이스

### 14.1 지원 로그인

로그인 화면은 국내 사용자를 고려해 다음 순서로 제공한다.

1. 카카오로 계속하기
2. 네이버로 계속하기
3. Google로 계속하기

`Gmail 로그인`이 아니라 `Google로 계속하기`라고 표시한다.

### 14.2 인증 흐름

1. 사용자가 소셜 로그인을 선택한다.
2. 제공자의 공식 OAuth/OIDC 화면에서 인증한다.
3. Sellform 서버가 인가 코드와 사용자 식별자를 검증한다.
4. 최초 로그인 시 사용자와 개인 워크스페이스를 만든다.
5. 서버가 안전한 세션 쿠키를 발급한다.
6. 모든 프로젝트·자산·크레딧·다운로드 요청에서 소유권을 확인한다.

### 14.3 보안 원칙

- 토큰과 세션을 브라우저 `localStorage`에 저장하지 않는다.
- `Secure`, `HttpOnly`, `SameSite` 쿠키를 사용한다.
- 프론트엔드가 전달한 사용자 ID·워크스페이스 ID를 신뢰하지 않는다.
- 계정은 `provider + provider_account_id`로 식별한다.
- 이메일이 같다는 이유만으로 계정을 자동 병합하지 않는다.
- 로그인한 사용자가 명시적으로 다른 소셜 계정을 연결한다.
- 마지막 로그인 수단을 실수로 해제하지 못하게 한다.
- 로그아웃, 전체 기기 로그아웃, 계정 연결 해제, 탈퇴를 지원한다.
- 로그인에 불필요한 제공자 접근 토큰은 장기 저장하지 않는다.

### 14.4 현재 개발 구조 이전

현재의 `X-Mock-User-Id`와 `X-Mock-Workspace-Id` 헤더는 개발·테스트 전용으로만 유지하고 운영 환경에서는 비활성화한다. 모든 API는 실제 서버 세션에서 사용자와 워크스페이스를 계산하도록 이전한다.

## 15. 크레딧·미리보기·결제

### 15.1 기본 정책

- 상품 분석과 제한된 미리보기를 무료로 제공한다.
- 고해상도 최종 결과를 내려받을 때 버전을 잠금 해제한다.
- AI 이미지 생성·재생성·대규모 디자인 변경은 크레딧을 사용한다.
- 이미 결제한 동일 버전은 다시 다운로드해도 추가 차감하지 않는다.
- 새로운 AI 이미지 또는 새로운 최종 버전은 필요한 작업량에 따라 크레딧을 사용한다.
- 기술적 실패로 사용 가능한 결과가 생성되지 않으면 차감하지 않거나 자동 환불한다.

### 15.2 결제 시점

사용자는 워터마크 또는 제한된 해상도의 전체 미리보기를 먼저 확인한다. 다운로드 버튼을 누르면 필요한 크레딧과 포함 항목을 명확히 보여주고 결제 또는 크레딧 사용을 승인받는다.

### 15.3 원장 원칙

- 현재 잔액만 저장하지 않고 모든 적립·차감·환불 거래를 원장으로 기록한다.
- 결제 요청과 크레딧 차감은 중복 실행되지 않도록 멱등성을 보장한다.
- 프로젝트, 버전, 생성 작업, 다운로드 권한과 거래를 연결한다.
- 가격과 차감 정책은 운영 설정으로 변경할 수 있게 한다.

결제 제공자는 별도 기술 검토 후 선정한다. 이 문서는 특정 결제사에 종속되지 않는다.

## 16. 주요 데이터 모델

- `User`: 내부 사용자
- `OAuthAccount`: 카카오·네이버·Google 계정 연결
- `Session`: 로그인 세션과 기기 정보
- `Workspace`: 개인 또는 팀 작업 공간
- `WorkspaceMembership`: 소유자·관리자·편집자 역할
- `BrandKit`: 브랜드 디자인과 표현 규칙
- `ProductProject`: 상품 단위 프로젝트
- `SourceCapture`: URL·확장 프로그램·직접 입력 출처
- `Asset`: 이미지와 권리·역할·품질 상태
- `ProductFact`: 사실·단위·근거·확인 상태
- `Storyboard`: 섹션 순서와 사용할 사실·자산
- `GenerationJob`: AI 생성 작업과 비용·실패 상태
- `DetailPageVersion`: 승인 가능한 상세페이지 버전
- `ExportArtifact`: 채널별 출력 파일
- `CreditWallet`: 워크스페이스 크레딧 지갑
- `CreditLedger`: 적립·차감·환불 원장
- `VersionEntitlement`: 결제한 버전의 다운로드 권한

## 17. 규제·저작권·표현 안전

- 공급처 원본 이미지와 디자인의 최종 사용 여부를 명시적으로 구분한다.
- 판매자가 자산 권리와 판매 자격을 확인할 수 있게 한다.
- 브랜드 로고와 인증 마크를 임의로 제거·추가하지 않는다.
- 의료·치료·질병 예방·효능 보장 문구를 자동 감지한다.
- `친환경`, `저소음`, 정확한 온도·시간·성능 등의 주장은 근거를 요구한다.
- 이미지 생성 결과에도 동일한 사실·규제 검사를 적용한다.
- 자동 생성 결과는 판매자의 최종 검수를 거쳐야 한다.

## 19. 성공 기준

- 링크가 차단돼도 직접 업로드 또는 브라우저 보조 수집으로 프로젝트를 완료할 수 있다.
- 숫자·단위·모델·포장 정보가 원문 근거와 연결된다.
- 충돌 사실이 자동 확정되지 않는다.
- 공급처 원본 디자인이 최종 결과에 그대로 노출되지 않는다.
- 하나의 기준 사진으로 만든 AI 장면이 상품 정체성을 유지한다.
- 최종 페이지가 단순 텍스트 카드가 아니라 이미지 중심 구매 흐름을 가진다.
- 스펙 섹션이 항상 마지막에 위치한다.
- 쿠팡과 스마트스토어 버전의 내용은 같고 규격·분할만 다르다.
- 미리보기와 다운로드 결과의 문구·순서·이미지가 일치한다.
- 로그인 사용자는 다른 사용자의 프로젝트·자산·크레딧에 접근할 수 없다.
- 같은 유료 버전의 재다운로드에는 추가 크레딧이 들지 않는다.
