# Sellform V2 Sprint 3 — 사실·증거·충돌 보드

상태: 구현 계획  
선행 조건: Sprint 2  
후속 Sprint: Sprint 4 스토리보드

## 1. 목표

링크, OCR, 판매자 입력에서 얻은 상품 정보를 하나의 사실 카드로 정규화하고, 근거와 충돌을 판매자가 확인한 뒤 생성에 사용할 수 있게 한다.

## 2. 사실 카드 구조

- 항목명과 카테고리
- 원문, 번역문, 정규화한 값과 단위
- 모델·옵션·본체·개별 포장·외박스 단위
- 출처 URL 또는 이미지·OCR 좌표
- 신뢰도와 추출기 버전
- 상태: 추출, 출처 확인, 판매자 확인, 검토 필요, 충돌, 거부
- 수정·승인 이력
- 상세페이지 사용 섹션과 문구

## 3. 처리 규칙

- 같은 의미의 단위와 표현을 하나의 후보 그룹으로 묶는다.
- 포장 무게와 본체 무게를 섞지 않는다.
- 모델별 스펙을 공통 스펙으로 자동 합치지 않는다.
- 서로 다른 값이 있으면 최신값을 임의 선택하지 않고 `conflicted`로 표시한다.
- 판매자가 입력한 사실은 다른 출처보다 우선할 수 있지만 변경 이력을 남긴다.
- 효능·인증·친환경·저소음·정확한 성능은 증거 수준에 따라 `needs_review`로 둔다.

## 4. YL-T02 검증 사례

- 전용 상세 이미지의 `4개 마사지 헤드`와 일반 상품 속성의 `6개 이상`을 충돌로 표시
- `10분`은 1회 작동 시간 후보, `2시간`은 총 사용 시간 후보로 분리
- 외박스 순중량 6kg을 본체 6kg으로 사용하지 않음
- YL-T02 본체 무게 1000g 후보와 포장·수량 정보를 분리
- `약 42°C`, `저소음`, `친환경`, `경추 보호`, `수면 개선`은 판매자 확인 또는 표현 순화 요구

## 5. 판매자 확인 UI

- 확정·검토 필요·충돌 탭
- 근거 이미지의 해당 위치 확대
- 원문과 번역 비교
- 값·단위·대상 모델 직접 수정
- 후보 선택, 사실 거부, 근거 추가
- 일괄 승인 전 위험 표현 재확인
- 생성에 사용 가능한 사실만 별도 요약

## 6. API·데이터

- 프로젝트 사실 목록·필터·근거 조회 API
- 후보 병합, 충돌 해결, 판매자 확인 API
- 승인 요청의 사용자·워크스페이스 권한 검사
- 사실 변경 시 영향을 받는 스토리보드와 페이지 버전 표시
- 생성 시점에 승인된 사실 스냅샷 저장

## 7. 제외 범위

- 판매 문구 자동 작성
- AI 이미지 생성
- 법률적 인증을 AI가 대신 판정하는 기능
- 사용자 승인 없는 자동 충돌 해결

## 8. 테스트

- 숫자·단위 정규화와 원문 보존
- 본체·포장·외박스 단위 분리
- 4개·6개 이상 충돌 생성과 해결 이력
- 다른 워크스페이스의 사실 승인 거부
- 거부·검토 필요 사실이 생성 입력에서 제외되는지 확인
- 사실 수정 후 의존 섹션을 오래된 상태로 표시

## 9. 완료 기준

- 모든 판매 수치가 한 개 이상의 근거와 연결된다.
- 충돌 사실은 판매자 승인 전 생성 입력에 들어가지 않는다.
- 판매자가 원문을 보며 값·단위·모델을 수정할 수 있다.
- 승인된 사실 스냅샷을 재현할 수 있다.

## 10. Sprint 4 진입 조건

HERO와 주요 기능, 구성품, 최종 스펙에 사용할 사실이 승인되거나 명시적으로 제외되어야 한다.
