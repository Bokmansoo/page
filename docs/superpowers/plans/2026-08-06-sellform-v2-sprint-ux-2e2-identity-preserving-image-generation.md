# Sellform V2 Sprint UX-2E-2: 정체성 보존 이미지 생성

상태: 기획 완료 · 이미지 API 키/예산 승인 대기  
선행: UX-2E-0, UX-2E-1  
후속: UX-2E-3 생성 결과 반영·검수·출력

## 1. 목적

판매자 보유 제품 사진을 기준으로 사람 사용 장면, 충전 장면, 기능 클로즈업을 생성한다. 단순히 예쁜 이미지를 만드는 것이 아니라 제품의 형태·색상·버튼·포트·구성품이 기준 사진과 맞는 결과만 판매 후보로 둔다.

```text
판매자 승인 장면 계획
  → 기준 사진·확정 사실·승인 카피 고정
  → 비용 확인
  → 이미지 제공자 요청
  → 정체성/OCR/권리 검사
  → 판매자 검토
  → 승인 결과만 상세페이지 후보
```

## 2. 생성 장면

- `hero_product`: 깨끗한 제품 중심 HERO. 필요 시 배경·조명만 바꾸고 제품 형태는 고정한다.
- `usage_scene`: 목·어깨 등 제품 목적에 맞는 실제 사용 맥락. 의료 효과나 과도한 표정은 금지한다.
- `feature_closeup`: 버튼, 열감 표시, 소재, 구성품 등 기준 사진에 실제로 보이는 요소만 강조한다.
- `charging_or_power`: 확인된 충전 포트·전원·배터리 사실이 있을 때만 생성한다.
- `spec_graphic`, `notice`: 이미지 생성 대신 UX-2E-1의 확정 사실 기반 한국어 HTML 카드가 기본이다.

## 3. 안전 계약

- 입력은 UX-2E-0의 판매자 승인 `ScenePlan`과 안전 기준 사진만 사용한다.
- 프롬프트에는 제품 정체성 유지·외국어 문구 금지·가격/QR/마켓 로고/타사 제품 금지를 강제한다.
- 공급처 캡처, 가격표, OCR 위험 사진은 생성 참고용으로도 기본 제외한다.
- 제품이 다르게 생성되었거나 외국어·가격·타사 로고가 보이면 자동 `failed` 또는 `needs_seller_review`로 보낸다.
- 생성 API가 원본을 학습/재사용할 수 있는지 제공자 약관을 확인하고, 고객 데이터 학습 거부 설정이 가능한 제공자만 사용한다.

## 4. 작업·비용·재시도

- 작업은 `draft → pending_provider → running → needs_seller_review → succeeded/failed/cancelled` 상태를 사용한다.
- 생성 전 장면 수, 해상도, 예상 크레딧/비용, 재생성 비용을 판매자에게 표시하고 승인받는다.
- 동일 장면 재시도는 이전 작업 ID·프롬프트 버전·기준 사진·실패 사유와 연결한다.
- 공급자 실패에는 차감하지 않거나 Sprint 16 원장에 자동 환불 거래를 남긴다.
- 브라우저에서 제공자 API를 직접 호출하지 않는다.

## 5. 구현 작업

### 백엔드

1. 실제 이미지 제공자 어댑터를 `GenerationProviderAdapter`에 연결한다.
2. 승인된 장면으로 요청을 만들고, 업로드 자산은 서명된 단기 URL 또는 서버 중계로만 제공한다.
3. `ImageGenerationJobRecord`와 UX-2E-0 작업 계약을 통합해 상태·비용·결과 자산·검사 결과·재시도를 저장한다.
4. 생성 자산에 정체성 유사도, OCR, 가격/QR/로고, 권리 상태 검사를 수행한다.
5. 실패 결과는 기존 안전 사진/HTML 정보를 유지하며 기존 최종본을 덮어쓰지 않는다.

### 프런트엔드

1. 장면별 기준 사진, 생성 목적, 예상 결과, 비용, 승인 상태를 최종 확인한다.
2. 생성 중/실패/검수 대기/완료 상태와 재시도 가능한 사유를 표시한다.
3. 생성된 이미지는 `판매자 검수 전` 배지를 붙이고 원본 사진과 나란히 비교한다.
4. 제품 불일치, 외국어·가격·타사 노출 경고가 있으면 승인 버튼을 막고 다른 결과/재생성을 제안한다.

## 6. 테스트

- YL-T02 기준 사진으로 생성한 HERO/사용/충전 장면에서 색상·버튼·포트·구성품 보존 검사를 통과/실패시키는 테스트를 작성한다.
- 외국어, 가격, QR, 타사 제품, 제품 형태 변경 결과가 최종 자산으로 승격되지 않는지 검증한다.
- API 타임아웃·비용 한도·판매자 취소·재시도 시 중복 청구 또는 기존 결과 손실이 없는지 검증한다.
- 생성 장면이 없는 경우에도 HTML 정보형 상세페이지와 다운로드가 유지되는지 검증한다.

## 7. 완료 조건

- API가 필요한 사용/충전/연출 장면만 실제 생성 요청된다.
- 생성 이미지는 정체성·OCR·권리 검사와 판매자 승인 전에는 최종 페이지에 반영되지 않는다.
- 비용·실패·재시도 이력이 장면과 버전에 연결된다.
- 중국어 공급처 이미지는 생성 결과의 최종 배경/텍스트로 재사용되지 않는다.
