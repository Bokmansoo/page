# Sellform V2 Sprint UX-2C: 업로드 사진 기반 상세페이지 완성

상태: 구현 완료 · 회귀 테스트 및 브라우저 E2E 검증 완료  
선행: UX-2B 규칙 기반 한국어 카피  
후속: UX-2D 판매용 콘텐츠 품질 고도화 → UX-2E LLM 텍스트·이미지 생성 API 연결

## 목표

이미지 생성 API와 LLM API 없이도 판매자가 올린 상품 사진을 실제 상세페이지의 HERO·기능·충전/사용·구성품·사양 섹션에 안전하게 배치한다. 결과 화면에서 사진을 직접 교체·제외·순서 변경할 수 있어야 하며, 저장한 결과와 PNG/JPG 다운로드 결과는 반드시 동일해야 한다.

이 Sprint는 새 이미지를 만들지 않는다. 판매자 직접 촬영 또는 사용 권한을 확인한 사진만 최종 출력에 사용한다.

## 사용자 흐름

```text
상품 사진 업로드
  → 사진 역할 제안(대표/기능/사용·충전/구성품/규격)
  → 기본 배치된 상세페이지 생성
  → 결과 화면에서 섹션별 사진 확인·교체·숨김·순서 변경
  → 저장
  → 동일한 페이지를 쿠팡/스마트스토어 규격 이미지로 다운로드
```

## 범위

### 1. 사진 사용 권한과 후보 분리

- 최종 출력 후보는 `seller_owned` 또는 판매자가 사용 권한을 명시적으로 확인한 사진만 포함한다.
- `reference_only`, `blocked`, 사용 권한 미확인 사진은 후보 목록에는 사유와 함께 보이되 최종 출력 선택은 막는다.
- 사진이 하나도 없거나 선택 가능한 사진이 없으면 이미지 칸을 빈 카드/HTML 정보 카드로 렌더링한다. `사진 필요` 같은 임시 문구를 최종 다운로드에 넣지 않는다.

### 2. 사진 역할 제안과 기본 배치

- 업로드 순서, 사용자가 지정한 역할, 이미지 검사 결과를 이용해 다음 역할을 제안한다.
  - `hero`: 제품 전체가 가장 잘 보이는 대표 사진
  - `feature`: 온열, 조작부, 소재 등 기능을 보여 주는 사진
  - `usage_or_charging`: 실제 사용, 충전, 조작 방법 사진
  - `components`: 구성품 배열 사진
  - `spec`: 크기·규격·포장 정보 사진
- 자동 배치는 제안일 뿐이다. 사용자가 고른 섹션 사진을 절대 덮어쓰지 않는다.
- 같은 사진을 여러 섹션에 반복 배치하지 않는다. 사진이 부족한 경우에는 우선순위가 높은 HERO 한 곳에만 사용하고 나머지는 텍스트/사양 레이아웃으로 유지한다.
- 사진의 역할·선택 근거·섹션 연결은 프로젝트와 페이지 버전에 저장한다.

### 3. 결과 화면의 섹션별 사진 편집

각 이미지 섹션에는 다음 동작을 제공한다.

- 사용 가능한 업로드 사진 후보 보기
- 사진 선택/교체
- 사진 숨김 또는 텍스트 레이아웃으로 전환
- 섹션 이미지 순서 변경
- 원본 비율 유지, `contain`/`cover` 중 안전한 표시 방식 선택
- 선택한 사진의 출처·권한 상태·연결된 사실 확인

사진 편집은 문구 인라인 편집과 같은 저장 흐름을 사용한다. 저장 실패 시 화면상 선택을 확정된 것처럼 표시하지 않는다.

### 4. 렌더링과 내보내기

- HERO는 선택된 대표 사진이 있으면 제품 사진 중심으로 렌더링한다. 없으면 UX-2B의 사실 기반 텍스트 HERO를 사용한다.
- 기능·사용·구성품·사양 섹션은 선택된 사진이 있을 때만 사진 블록을 렌더링한다.
- 원본 이미지는 비율을 보존하고, 잘림이 발생하면 편집 화면에서 명확하게 보여 준다.
- 미리보기, 결과 화면, `export-render`, 채널별 긴 이미지 및 분할 ZIP은 같은 페이지 버전의 같은 사진 연결을 사용한다.
- 내보내기 전 선택된 이미지 URL의 로드 실패·권한 차단을 검사한다. 실패한 이미지는 다운로드를 막고 해당 섹션으로 안내한다.

## 데이터·API 계약

### 저장 데이터

- `Asset`: 파일, 소유/사용 권한 상태, 이미지 검사 결과, 역할 힌트
- `PageSection.visual_payload`: 선택된 `asset_id`, 렌더 방식, 표시 순서, 선택 상태
- `PageSection.associated_fact_ids`: 해당 섹션 문구/사양의 근거 사실
- `DetailPageVersion.sections_json`: 위 사진 연결과 근거 연결을 모두 포함

### API

- 페이지 조회 응답은 섹션별 선택 사진과 선택 가능한 사진 후보(권한 상태 포함)를 제공한다.
- 페이지 저장 요청은 섹션별 `asset_id`, `render_mode`, `display_order`, `hidden` 변경을 원자적으로 저장한다.
- 사용 불가 사진을 선택하려 하면 `422`와 차단 이유를 반환한다.
- 내보내기 요청은 확정된 페이지 버전 ID를 사용하며, 최신 초안이나 다른 프로젝트의 사진을 섞어 쓰지 않는다.

## 완료 조건

- 판매자가 올린 사용 가능 사진 1장 이상이 HERO 또는 적절한 섹션에 실제로 표시된다.
- 업로드 사진 4장 이상이면 대표·기능·사용/충전·구성품/사양을 가능한 범위에서 서로 다른 사진으로 제안한다.
- 사진이 부족해도 최종 PNG/JPG에 `사진 필요`, 빈 업로드 안내, 개발용 자리표시자가 나타나지 않는다.
- 사용 불가 사진은 최종 페이지·미리보기·다운로드에 포함되지 않는다.
- 결과 화면에서 사진을 교체/숨김/순서 변경한 후 저장하면 새로고침과 버전 복원 뒤에도 유지된다.
- 미리보기와 다운로드 이미지에서 선택 사진·문구·섹션 순서가 일치한다.
- 같은 입력으로 다시 생성해도 이미 판매자가 편집한 사진 연결을 자동으로 덮어쓰지 않는다.

## 테스트 계획

- 역할 제안 단위 테스트: 대표/기능/사용·충전/구성품/규격 후보와 중복 방지
- 권한 정책 테스트: `seller_owned` 허용, `reference_only`/`blocked` 차단
- 페이지 저장 API 테스트: 사진 교체·숨김·순서·버전 복원
- 렌더/내보내기 계약 테스트: 현재 확정 버전의 선택 사진만 사용하고 로드 실패를 차단
- Playwright E2E: 사진 업로드 → 자동 배치 → 교체 → 저장 → PNG/분할 ZIP 다운로드

## 명시적 비범위

- 사람 사용 장면, 충전 장면 등의 신규 AI 이미지 생성
- LLM을 이용한 문구 재작성
- 공급처·경쟁사 사진의 권한 우회 또는 최종 출력 사용
- 자유형 캔버스 편집기

## UX-2D·UX-2E 전환 기준

UX-2D에서는 UX-2C의 사진 권한 확인, 섹션 연결, 버전 고정, 미리보기-다운로드 일치 규칙을 유지하면서 반복 문구·중복 사진·외국어 포함 이미지·상품명과 파일명 품질을 먼저 개선한다. UX-2D 완료 후에도 판매자 사진이 부족한 경우에만 UX-2E에서 이미지 생성 API를 제안한다. LLM/이미지 API는 앞 단계의 규칙을 대체하지 않고 그 위에 추가한다.
