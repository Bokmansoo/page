# Sellform V2 Sprint 10 — 개인 데이터 격리 보안 보완

상태: 구현 계획  
선행 조건: Sprint 9  
후속 Sprint: Sprint 11 DB·마이그레이션 안정화

## 1. 목표

계정, 프로젝트, 업로드 사진, 상세페이지, 출력 파일을 워크스페이스 경계로 완전히 분리하고 URL이나 ID를 알아도 다른 워크스페이스 자료에 접근할 수 없게 한다.

## 2. 구현 범위

- `/uploads` 공개 정적 마운트를 제거한다.
- 원본·파생·AI 생성 이미지와 다운로드 파일은 인증 API를 통해서만 제공한다.
- 모든 프로젝트 하위 조회·수정·삭제에서 서버 세션의 `workspace_id`를 강제한다.
- 요청의 `user_id`, `workspace_id`, 소유자 값은 권한 판단에 사용하지 않는다.
- 공통 `workspace scoped` 조회 도우미를 도입해 필터 누락을 줄인다.
- 개발용 Mock 인증은 테스트 설정에서만 켤 수 있게 한다.
- 파일 경로, 오류 응답, 로그에 민감한 로컬 경로와 콘텐츠가 노출되지 않게 한다.

### 2.1 개발·스테이징 검증 계정

- 개발·스테이징 환경에만 반복 실행해도 중복 생성되지 않는 테스트 계정 시드를 제공한다.
- `dev-owner-1`, `dev-owner-2`는 서로 다른 개인 워크스페이스를 소유하는 일반 사용자다. 두 계정은 실제 사용자와 동일하게 서버 세션·권한 검사·파일 접근 정책을 적용받으며, Mock 헤더나 데이터 우회 권한을 갖지 않는다.
- `platform_admin`은 운영 통계와 감사 로그를 검증하기 위한 제한된 역할이다. 고객 사진, 상세페이지 본문, 파일 다운로드, OAuth·세션 토큰에는 기본 접근 권한이 없다.
- 시드 계정의 비밀번호·토큰·OAuth 비밀값을 저장소에 넣지 않는다. 개발 환경에서는 명시적 개발 로그인 또는 테스트 세션을 사용하고, 스테이징에서는 별도 비밀 관리값으로 로그인 수단을 구성한다.
- 운영 환경에서는 이 시드를 자동 실행하지 않으며, 운영자 계정 생성·권한 부여는 별도 승인과 감사 로그를 거친다.

## 3. 테스트

- 사용자 A가 사용자 B의 프로젝트·자산·페이지·팩트·출력 ID로 접근하면 `404` 또는 `403`
- 파일명을 추측하거나 기존 `/uploads/...` URL을 호출해도 비인증 접근 차단
- 팀 초대 전 접근 차단, 초대 수락 후 역할 범위 내 접근 허용
- 목록·상세·수정·삭제·생성·다운로드 전 API에 대한 교차 워크스페이스 회귀 테스트
- `dev-owner-1`과 `dev-owner-2`로 같은 시나리오를 실행해 상호 프로젝트·자산·출력 접근이 차단되는지 확인
- `platform_admin` 응답에 고객 콘텐츠·파일 URL·OAuth·세션 비밀값이 없는지 확인

## 4. 완료 기준

- 공개 파일 경로가 없다.
- 보호 대상 API의 워크스페이스 필터 누락 검사가 완료된다.
- 교차 워크스페이스 및 비인증 파일 접근 테스트가 모두 통과한다.
- 개발·스테이징에서 두 일반 테스트 계정과 제한된 운영자 계정을 재현 가능하게 만들 수 있다.
- 테스트 계정과 운영자 역할 모두 고객 데이터 격리 정책을 우회하지 않는다.
- 보안 검토 기록에 미해결 Critical/High 항목이 없다.

## 5. 제외 범위

- 결제와 크레딧
- 운영자 통계 화면
- 공개 템플릿 등록
- 운영용 객체 저장소 배포

Sprint 10을 통과하기 전에는 실제 고객 데이터나 유료 기능을 운영하지 않는다.
