# Sellform V2 Sprint 9 — 소셜 로그인·워크스페이스·권한

상태: 구현 계획  
선행 조건: Sprint 8  
후속 Sprint: Sprint 10 개인 데이터 격리 보안 보완

## 1. 목표

개발용 Mock 사용자 헤더를 실제 서버 세션으로 교체하고 카카오·네이버·Google 로그인, 계정 연결, 워크스페이스 소유권을 안전하게 구현한다.

## 2. 로그인 제공자

사용자 화면 순서:

1. 카카오로 계속하기
2. 네이버로 계속하기
3. Google로 계속하기

개발 순서는 표준 OIDC 흐름 검증이 쉬운 Google 기반을 먼저 만들고 같은 내부 인증 계약에 카카오와 네이버를 연결한다.

## 3. 인증 흐름

1. 제공자 로그인 시작 요청과 `state`, `nonce`, PKCE 정보를 만든다.
2. 공식 OAuth/OIDC 화면에서 사용자가 인증한다.
3. 서버가 인가 코드, 토큰, 발급자, 대상, 만료를 검증한다.
4. `provider + provider_account_id`로 내부 사용자를 찾는다.
5. 최초 로그인 시 개인 워크스페이스와 멤버십을 만든다.
6. `Secure`, `HttpOnly`, `SameSite` 세션 쿠키를 발급한다.
7. API는 세션으로 사용자와 워크스페이스 권한을 계산한다.

## 4. 계정 연결 정책

- 이메일이 같다는 이유로 소셜 계정을 자동 병합하지 않는다.
- 로그인한 사용자가 재인증 후 다른 제공자를 명시적으로 연결한다.
- 같은 제공자 계정이 둘 이상의 내부 사용자에 연결되지 않는다.
- 마지막 로그인 수단은 대체 수단 없이 해제하지 못한다.
- 로그아웃, 모든 기기 로그아웃, 계정 연결 해제, 탈퇴를 제공한다.
- 제공자 이메일이 없거나 비공개여도 안정적인 제공자 ID로 동작한다.

## 5. 워크스페이스 권한

- 소유자, 관리자, 편집자 역할
- 프로젝트, 자산, 사실, 버전, 출력, 크레딧을 워크스페이스 범위로 제한
- URL 파라미터, 헤더, 요청 본문의 사용자·워크스페이스 ID를 신뢰하지 않음
- 소유권 변경과 멤버 초대는 후속 확장 가능하게 모델링

## 6. 확장 프로그램 연결

- Sprint 8 연결 코드를 실제 로그인 사용자와 워크스페이스에 연결
- 확장 토큰은 웹 세션과 분리된 짧은 수명·제한 범위 토큰
- 기기 목록과 연결 해제 제공

## 7. 데이터·API

- `User`, `OAuthAccount`, `Session`, `Workspace`, `WorkspaceMembership`
- 로그인 시작·콜백·세션 조회·로그아웃·전체 로그아웃
- 계정 연결 시작·콜백·해제
- 세션 회전, 만료, 폐기, 기기 정보
- 운영 환경에서 `X-Mock-User-Id`, `X-Mock-Workspace-Id` 비활성화
- 테스트 환경에서만 명시적 설정으로 Mock 인증 허용

## 8. 개인정보·보안

- 최소 프로필 범위만 요청
- 로그인에 불필요한 제공자 접근 토큰 장기 저장 금지
- 필요한 토큰은 암호화하고 만료·폐기 처리
- 로그인·연결·해제·탈퇴 감사 로그
- CSRF, 세션 고정, 리플레이, 오픈 리다이렉트 방어
- 탈퇴 시 보존 의무와 삭제 대상을 분리

## 9. 제외 범위

- 기업 SSO
- 비밀번호 직접 가입
- 유료 크레딧 결제
- 마켓 판매자 계정 연결

## 10. 테스트

- 세 제공자 성공·거부·콜백 오류
- `state`, `nonce`, PKCE, 만료 토큰 실패
- 이메일 중복 계정의 자동 병합 금지
- 계정 연결·해제와 마지막 수단 보호
- 워크스페이스 간 프로젝트·자산·출력 접근 차단
- 운영 모드 Mock 헤더 무시
- 확장 토큰 범위·만료·폐기

## 11. 완료 기준

- 세 로그인 방식으로 같은 내부 사용자·워크스페이스 계약을 사용한다.
- 브라우저 `localStorage`의 Mock ID 없이 전체 프로젝트 흐름이 동작한다.
- 다른 사용자의 프로젝트와 다운로드에 접근할 수 없다.
- 인증·연결·로그아웃·탈퇴 흐름을 재현 가능한 테스트가 보호한다.

## 12. Sprint 10 진입 조건

개인 데이터 격리 보완을 시작할 수 있도록 모든 API가 실제 세션에서 사용자와 활성 워크스페이스를 계산하고, 다른 워크스페이스의 프로젝트·자산·출력 접근을 차단해야 한다.
