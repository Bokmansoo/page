# Sellform V2 Sprint 0 — 기준선·권리·품질 정책

상태: 구현 전 보완 계획  
선행 조건: V2 최종 기획 승인  
후속 Sprint: Sprint 1 상품 자료 묶음 입력

## 1. 목표

기준 상품과 공통 평가표를 고정하고, 공급처 자료의 참고 전용 정책과 스펙 마지막 배치 규칙을 시스템 계약으로 만든다. 이후 모든 Sprint는 같은 기준 상품과 판정 규칙으로 회귀 검증한다.

## 2. 사용자 결과

- 팀이 “보기 좋다”가 아니라 동일한 평가 기준으로 결과를 비교한다.
- 공급처 자료가 최종 상세페이지에 무단으로 섞이지 않는다.
- 확인되지 않은 상품 사실과 과장 표현이 기준선부터 차단된다.

## 3. 범위

### 3.1 기준 상품

- 해외 소싱 리빙: 1688 `996262285530`, YL-T02 마사지 베개
- 생활용품: 링크·사진·스펙을 갖춘 상품 1종 추가 선정
- 뷰티: 전성분·용량·사용법을 갖춘 상품 1종 추가 선정
- 선택 기준: 대표컷, 기능·상세 이미지, 스펙 근거, 기준 출력 JPG 확보 가능 여부

### 3.2 정책 계약

- 자산 상태: `reference_only`, `seller_owned`, `ai_generated`, `derived_graphic`, `blocked`
- 사실 상태: `extracted`, `source_confirmed`, `seller_confirmed`, `needs_review`, `conflicted`, `rejected`
- 공급처 원본 디자인과 카피는 최종 출력에 기본적으로 사용하지 않는다.
- 상세 제품 스펙과 필수 고지는 최종 섹션에 고정한다.
- 의료·효능·친환경·저소음·정확한 성능 수치는 근거와 확인 상태를 요구한다.

### 3.3 평가표

- HERO에서 상품 식별 가능 여부
- 섹션별 서로 다른 이미지 또는 그래픽 사용
- 이미지 반복과 공급처 배너 노출 여부
- 수치·성능 문구의 근거 연결 여부
- 문제→제품→기능→사용→신뢰→CTA→최종 스펙 흐름
- 빈 섹션과 자료 부족 안내 품질
- 미리보기와 JPG/PNG의 순서·문구·이미지 일치

## 4. 데이터·API·화면

- 기준 상품 등록 구조에 상품, 자산 묶음, 참고 캡처, 기준 출력, 평가 결과를 저장한다.
- 자산과 사실의 V2 상태 값을 enum 또는 검증 가능한 상수로 정의한다.
- 기준 상품 조회 API는 기준 키, 카테고리, 필수 이미지 역할, 참고 구조, 평가 항목을 반환한다.
- 내부 기준선 화면 또는 JSON에서 세 상품의 준비 상태를 확인한다.

## 5. 제외 범위

- 실제 OCR, 이미지 생성, 소셜 로그인, 결제 구현
- 공급처 사이트 접근 제한 우회
- 기준 상품을 그대로 사용자 템플릿으로 배포하는 기능

## 6. 테스트

- 기준 상품 3종 등록·조회 계약 테스트
- `reference_only` 자산을 최종 출력 후보로 지정할 때 거부되는 테스트
- 스펙이 마지막이 아닌 스토리보드를 유효하지 않게 판정하는 테스트
- 근거 없는 수치와 충돌 사실이 승인되지 않는 테스트
- 기준 출력 JPG와 평가 기록의 연결 테스트

## 7. 완료 기준

- 기준 상품 3종과 기준 출력·평가표가 저장된다.
- YL-T02의 `4개 헤드 ↔ 6개 이상` 충돌과 위험 표현이 기준 데이터에 포함된다.
- 자산 권리 상태와 사실 확인 상태가 코드·DB·API에서 동일하게 정의된다.
- `reference_only`와 스펙 마지막 정책을 자동 테스트가 보호한다.

## 8. Sprint 1 진입 조건

기준 상품, 상태 계약, 평가표, 최종 출력 금지 정책 중 하나라도 테스트로 고정되지 않으면 Sprint 1을 완료 처리하지 않는다.
