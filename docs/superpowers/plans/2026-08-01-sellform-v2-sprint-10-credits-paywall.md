# Sellform V2 Sprint 10 — 크레딧·결제·버전 잠금 해제

상태: 구현 계획  
선행 조건: Sprint 9  
후속 Sprint: Sprint 11 품질·규제·보안 검증

## 1. 목표

무료 미리보기 후 사용자가 필요한 고해상도 버전과 AI 작업에만 비용을 지불하고, 같은 버전 재다운로드와 기술 실패 환불을 정확히 처리한다.

## 2. 과금 단위

- AI 이미지 신규 생성
- AI 이미지 재생성 또는 큰 변경
- 최종 고해상도 버전 잠금 해제
- 정책상 유료인 추가 채널·추가 버전

텍스트 입력, 사실 확인, 제한된 미리보기는 기본 무료 범위로 둔다. 정확한 가격과 무료 한도는 운영 설정으로 관리한다.

## 3. 사용자 흐름

1. 전체 페이지를 제한 해상도 또는 워터마크 미리보기로 확인한다.
2. AI 작업 실행 전 예상 크레딧을 확인하고 승인한다.
3. 다운로드 시 잠금 해제할 버전·채널·포맷·비용을 확인한다.
4. 잔액이 부족하면 크레딧 결제로 이동한다.
5. 결제 성공 후 원장 적립과 버전 권한을 처리한다.
6. 이미 잠금 해제한 동일 버전은 추가 차감 없이 재다운로드한다.

## 4. 원장과 권한

- `CreditWallet`: 빠른 잔액 조회
- `CreditLedger`: 구매, 보너스, 차감, 예약, 취소, 환불, 만료
- `VersionEntitlement`: 사용자·워크스페이스·페이지 버전·포함 채널·포맷
- 모든 거래에 프로젝트, 생성 작업, 결제, 출력 버전을 연결
- 잔액은 원장 합계와 정기적으로 대조

## 5. 멱등성과 실패 처리

- 결제 승인, 웹훅, 크레딧 차감, 작업 실행에 각각 멱등성 키 사용
- 생성 전 예약 후 성공 시 확정, 기술 실패 시 예약 취소
- 사용자 취소, 안전 차단, 제공자 오류를 구분해 환불 정책 적용
- 사용 가능한 결과가 생성되지 않은 기술 실패는 차감하지 않거나 자동 환불
- 결제 성공과 권한 발급 사이 장애를 재처리 가능하게 저장

## 6. 결제 제공자 추상화

- 결제 준비, 승인, 취소, 웹훅 검증 인터페이스
- 제공자 키와 웹훅 비밀정보는 서버 비밀 저장소 사용
- 결제사 선정 전 Mock 제공자로 전체 계약 테스트
- 카드 정보는 Sellform 서버에 직접 저장하지 않는다.

## 7. 화면

- 현재 크레딧과 사용 내역
- 작업별 예상·실제 사용량
- 미리보기와 고해상도 차이 안내
- 버전 잠금 해제 모달
- 결제 성공·실패·처리 중 복구 화면
- 이미 구매한 버전 배지와 재다운로드

## 8. 제외 범위

- 월 구독제 자동 갱신은 베타 이후 가격 검증 후 결정
- 판매 수수료 정산
- 마켓 주문 결제
- 환율 기반 실시간 가격 변경

## 9. 테스트

- 원장 합계와 잔액 일치
- 동일 요청·웹훅 중복 처리 방지
- 잔액 부족과 동시 차감 경쟁 조건
- 생성 실패 예약 취소·환불
- 동일 버전 재다운로드 무차감
- 다른 사용자의 권한 재사용 차단
- 결제 성공 후 권한 발급 장애 복구

## 10. 완료 기준

- 무료 미리보기에서 유료 잠금 해제까지 전체 흐름이 동작한다.
- 모든 크레딧 변화가 원장으로 설명된다.
- 기술 실패와 중복 요청이 사용자의 크레딧을 잘못 차감하지 않는다.
- 같은 버전의 쿠팡·스마트스토어 결과를 정책 범위에서 재다운로드할 수 있다.

## 11. Sprint 11 진입 조건

실제 돈을 받기 전에 인증, 소유권, 원장, 웹훅, 실패 환불의 보안 테스트가 모두 통과해야 한다.
