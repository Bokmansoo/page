# Sellform V2 Sprint 11 — DB 구조·마이그레이션 안정화

상태: 구현 계획  
선행 조건: Sprint 10  
후속 Sprint: Sprint 12 팀 워크스페이스 완성

## 1. 목표

실행 시 임시 `ALTER TABLE`에 의존하지 않고 개발·스테이징·운영 DB가 같은 버전의 스키마를 재현하고 안전하게 롤포워드·복구할 수 있게 한다.

## 2. 구현 범위

- Alembic 기반 정식 마이그레이션을 도입한다.
- `User → Workspace → Project → 하위 데이터` 소유 관계를 문서화하고 FK·인덱스·삭제 정책을 정리한다.
- 프로젝트 하위 엔터티는 직접 또는 검증 가능한 관계로 워크스페이스에 귀속한다.
- 감사 로그, 세션, 초대, 파일 메타데이터의 보존·삭제 정책을 정의한다.
- 기존 Docker PostgreSQL 데이터를 백업한 뒤 신규 스키마로 이전하는 절차를 만든다.
- PostgreSQL RLS 적용 여부를 결정하고, 적용 시 애플리케이션 테스트와 함께 정책을 버전 관리한다.

## 3. 테스트

- 빈 DB에 전체 마이그레이션 적용
- 현재 개발 DB 스냅샷의 롤포워드와 데이터 보존 검증
- FK 위반, 고아 데이터, 중복 멤버십, 필수 tenant 값 누락 차단
- 백업 복원 후 핵심 프로젝트와 파일 메타데이터 일치 검증

## 4. 완료 기준

- 신규·기존 DB가 동일한 최신 스키마에 도달한다.
- 애플리케이션 시작 코드가 임의 DDL을 수행하지 않는다.
- 마이그레이션과 복구 절차가 CI 또는 반복 가능한 실행 문서로 검증된다.
