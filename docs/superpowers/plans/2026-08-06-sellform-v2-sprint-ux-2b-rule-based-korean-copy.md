# Sellform V2 Sprint UX-2B: API 없는 스펙 기반 한국어 판매 카피

상태: 구현 완료 · 검증 완료  
선행: UX-2A 쿠팡형 Mock 출력

## 목표

텍스트 LLM API 없이도 판매자가 입력·승인한 상품 사실을 한국어 판매 상세페이지 초안으로 바꾼다. Mock 기본 문구와 영문 필드명 노출을 없애고, 카테고리별 구매 흐름에 맞춘 제목·보조 문구·정보 카드를 생성한다.

이 Sprint는 사실을 새로 만들지 않는다. 이미 확인된 상품 정보의 표현과 순서만 바꾸며, 사용자는 결과를 바로 수정할 수 있다.

## 범위

### 1. 사실 기반 카피 규칙

- 내부 필드명(`battery_capacity`, `rated_power`)을 한국어 표시명으로 변환한다.
- 값·단위는 확정 사실 원문을 사용한다.
- 제품명·카테고리·판매자 입력 설명을 조합해 HERO 제목과 보조 문구를 구성한다.
- 동일 필드가 여러 개면 모델·옵션·본체/포장 단위를 표시해 혼동을 막는다.
- 스펙이 없는 섹션은 일반적인 구매 전 확인 안내를 사용하며, 기능·효능을 추정하지 않는다.

### 2. 카테고리 템플릿

- 1차: 마사지기·건강 소형가전
- 후속: 주방가전, 생활가전, 뷰티, 수납·리빙
- 마사지기 기본 흐름:

```text
HERO → 사용 대상/구매 전 확인 → 핵심 사양 3개 → 사용·충전 안내 → 구성품·디테일 → 사양·주의사항·필수 고지
```

- `충전 안내`는 충전·전원 관련 확정 사실이 있을 때만 노출한다. 없으면 `사용 전 안내`로 표시한다.
- 구성품 섹션은 구성품 사실이 있을 때만 구체적 항목을 노출한다.

### 3. 표시명과 문구 사전

| 내부 필드 | 고객용 표시명 예시 | 문구 규칙 |
| --- | --- | --- |
| `battery_capacity` | 배터리 용량 | 값과 단위만 표시, 사용 시간 추정 금지 |
| `rated_power` | 정격 소비전력 | 값과 단위만 표시 |
| `rated_input` | 정격 입력 | 전원·충전 정보 섹션에 배치 |
| `charging_port` | 충전 방식 | 확정된 포트명만 표시 |
| `single_operation_time` | 1회 권장 사용 시간 | 권장·자동 종료 등은 근거가 있을 때만 표시 |
| `product_size` | 제품 크기 | 본체/포장 단위를 구분해 표시 |
| `model_name` | 모델명 | 옵션과 함께 마지막 사양표에 유지 |
| `components` | 구성품 | 판매자가 제공한 항목만 나열 |

### 4. 편집 UX

- 결과 화면에서 HERO, 각 핵심 정보, 사용 안내, 구성품 제목·본문을 인라인 편집한다.
- 수정된 문구는 해당 프로젝트·워크스페이스에만 저장한다.
- 수치·모델·단위·구성품이 포함된 문구를 수정할 때는 연결된 사실을 표시한다.
- 사용자가 근거 없는 인증·안전·치료·보증·A/S 표현을 입력하면 경고하고 저장 전 재확인한다.
- `원본 스펙으로 되돌리기`를 제공한다.

## 출력 예시: 목 마사지기

입력 사실: 2000mAh, 8W, DC 5V 2A, 10분, 40 × 17 × 15cm

```text
HERO: 목과 어깨 휴식 시간을 위한 온열 마사지 베개
보조: 판매자가 확인한 제품 사양과 사용 전 정보를 한눈에 정리했습니다.

핵심 정보 1: 충전식 배터리로 간편하게
본문: 배터리 용량은 2000mAh입니다.

핵심 정보 2: 제품 크기 확인
본문: 본체 크기는 40 × 17 × 15cm입니다.

핵심 정보 3: 전원 정보 확인
본문: 정격 입력은 DC 5V 2A, 정격 소비전력은 8W입니다.

사용 전 안내: 1회 권장 사용 시간과 상세 주의사항은 판매자 제공 정보를 확인해 주세요.
```

`피로 회복`, `통증 완화`, `안전 검증`, `의료 효과`, `무상 A/S`처럼 근거가 없는 표현은 생성하지 않는다.

## 데이터와 구현 경계

- 입력: `ProductFact` 중 판매자 승인 또는 출처 확인된 사실, 제품명, 카테고리, 판매자 설명.
- 출력: `PageSection.title`, `body_copy`, `visual_payload`의 사실 연결 카드.
- 텍스트 LLM API는 호출하지 않는다.
- 이미지 API는 호출하지 않는다.
- UX-2C에서 규칙형 카피 생성기 인터페이스를 유지한 채 LLM 구현체를 추가한다.

## 완료 기준

- 마사지기 새 프로젝트에서 영문 내부 필드명이 고객용 화면에 노출되지 않는다.
- 확정 사실 3개 이상이 있으면 서로 다른 한국어 핵심 정보 3개를 만든다.
- 충전·구성품 관련 사실이 없을 때 해당 내용을 단정하지 않는다.
- 모든 수치·단위·모델·구성품 문구가 연결된 사실을 가진다.
- 사용자가 카피를 수정·되돌리기 할 수 있다.
- 공급처 참고 이미지·경쟁사 문구는 최종 출력에 포함되지 않는다.
- PNG 미리보기와 다운로드의 문구가 일치한다.

## 테스트

- 필드명 → 한국어 표시명 단위 테스트
- 마사지기 카테고리 템플릿 단위 테스트
- 근거 없는 금지 문구 차단 테스트
- 인라인 편집 저장·되돌리기 API 테스트
- Mock 결과 → 편집 → PNG 다운로드 E2E 테스트

## 후속 Sprint 전환 기준

UX-2C는 이 규칙형 카피에 판매자 사진 배치와 편집을 연결하고, UX-2D는 반복 문구·사진 중복·외국어 노출·상품명과 파일명 품질을 개선한다. UX-2E에서 LLM API를 연결한 뒤에도 사실 선택·검증·금지 문구 검사, 카테고리별 섹션 순서와 마지막 사양표, 인라인 편집과 되돌리기, 공급처 참고 자료의 최종 출력 제외를 유지한다. LLM은 제목·본문 초안만 개선하며 승인되지 않은 사실을 추가할 수 없다.
