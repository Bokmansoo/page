# Sellform 이미지 API 없는 상품 비주얼 자동 조합 기획

작성일: 2026-07-31  
상태: 기획 확정 전 사용자 검토  
우선순위: 상세페이지 품질 개선 1순위

## 1. 배경

현재 Sellform의 Mock 이미지 생성기는 실제 상품 비주얼 대신 빨간색 사각형 이미지를 만든다.
Real 이미지 모드로 전환하면 외부 이미지 생성 API와 비용이 필요하며, 생성형 모델이 상품의
형태, 색상, 구성품을 임의로 바꿀 위험도 있다.

상세페이지에서 가장 중요한 것은 새로운 이미지를 발명하는 것이 아니라 판매자가 제공한
실제 상품 사진을 정확하게 보여주고, 확인된 상품 정보와 판매 문구를 읽기 좋은 디자인으로
조합하는 것이다.

따라서 Sellform의 기본 비주얼 생성 방식을 다음과 같이 전환한다.

```text
기존 방식
상품 정보 → AI 이미지 생성 → 텍스트 오버레이 → 상세페이지

변경 방식
실제 상품 사진 → 자동 보정·배치 → HTML/CSS 디자인 조합 → PNG/JPG
```

외부 이미지 생성 API는 기본 요구사항에서 제외한다. 향후 선택 기능으로 추가할 수 있지만,
API가 없어도 업로드 가능한 상세페이지가 완성되어야 한다.

## 2. 제품 목표

판매자가 상품 사진, 상품 URL, 상품 정보를 입력하면 Sellform이 다음 작업을 자동으로
수행한다.

1. 실제 상품 사진을 수집하고 용도를 분류한다.
2. 사진의 배경, 여백, 비율과 품질을 점검한다.
3. 상품 정체성을 훼손하지 않는 범위에서 크롭, 배치, 배경, 그림자를 적용한다.
4. 확인된 상품 정보로 제목, 설명, 배지, 장점 카드와 스펙 표를 구성한다.
5. 실제 상품 사진과 HTML/CSS 그래픽을 결합해 상세페이지를 렌더링한다.
6. 미리보기와 동일한 결과를 PNG/JPG로 다운로드한다.

핵심 제품 약속은 다음과 같다.

> 이미지 생성 API 없이도 실제 상품 사진만으로 업로드 가능한 상세페이지를 만든다.

## 3. 비목표

이번 단계에서는 다음 기능을 구현하지 않는다.

- Stable Diffusion, FLUX, ComfyUI 등 로컬 생성형 이미지 모델 연동
- OpenAI 등 외부 이미지 생성 API 호출
- 존재하지 않는 사용 장면이나 모델 사진 생성
- 상품 사진에 없는 구성품 또는 기능 합성
- 영상 또는 숏폼 MP4 렌더링
- 카드뉴스 전용 편집기

카드뉴스와 숏폼은 향후 동일한 상품 자산과 디자인 조합 엔진을 재사용하는 별도 단계로 둔다.

## 4. 핵심 원칙

- 상품 본체는 반드시 업로드 또는 허용된 출처에서 수집한 실제 사진을 사용한다.
- 생성형 AI가 상품 모양, 색상, 로고 또는 구성품을 새로 그리지 않는다.
- 한글 제목, 수치, 표, 배지와 아이콘은 HTML/CSS/SVG로 렌더링한다.
- 확인되지 않은 수치와 효능은 결과물에 포함하지 않는다.
- 원본 사진은 보존하고 모든 변환은 파생 자산으로 저장한다.
- 자동 크롭으로 상품 일부가 잘리거나 왜곡되지 않아야 한다.
- 미리보기와 PNG/JPG는 동일한 DOM과 스타일을 사용한다.
- 자동 결과가 부적합하면 판매자가 사진과 레이아웃을 직접 교체할 수 있어야 한다.

## 5. 사용자 흐름

```text
1. 상품 URL·사진·설명 입력
2. 실제 상품 이미지 수집
3. 상품 정보와 이미지 자동 분석
4. 판매자가 사실과 대표 이미지를 확인
5. 상세페이지 템플릿 선택
6. 섹션별 비주얼 자동 조합
7. 제목·문구·사진·배치 수정
8. 최종 검수
9. PNG/JPG 다운로드
```

이미지 수가 부족해도 빨간 사각형을 노출하지 않는다. 사진이 필요한 섹션은 실제 사진을
안전하게 재사용하거나 HTML/CSS 그래픽으로 전환한다. 두 방법 모두 적합하지 않으면 해당
섹션을 결과에서 제외하고 판매자에게 필요한 사진을 안내한다.

## 6. 이미지 입력과 분류

### 6.1 입력 경로

- 사용자가 직접 업로드한 상품 사진
- 상품 URL에서 수집한 사용 허가 범위 내 이미지
- 판매자가 추가한 상세, 구성품, 사용 장면 사진
- 기존 프로젝트에 저장된 승인 이미지

### 6.2 자동 역할 분류

각 이미지는 다음 역할 후보를 가진다.

| 역할 | 설명 | 주요 사용 위치 |
| --- | --- | --- |
| `product_main` | 상품 전체가 분명하게 보이는 대표 사진 | HERO, 상품 소개 |
| `product_detail` | 버튼, 재질, 구조 등 세부 사진 | 기능 설명 |
| `usage_scene` | 실제 사용 중인 장면 | 사용 맥락 |
| `package` | 패키지와 배송 상태 | 구매 전 확인 |
| `components` | 본품과 구성품 | 구성품 안내 |
| `spec_reference` | 라벨, 규격, 설명서 | 스펙 확인 |

자동 분류 결과에는 신뢰도를 포함하며 판매자가 역할을 바꿀 수 있다.

### 6.3 품질 검사

- 최소 해상도
- 과도한 압축 또는 흐림
- 상품이 프레임 밖으로 잘렸는지 여부
- 투명 배경 여부
- 이미지 비율
- 동일 이미지 중복
- 텍스트가 포함된 원본인지 여부
- 상품 정체성 확인 가능 여부

## 7. 비주얼 자동 조합 방식

### 7.1 허용되는 이미지 처리

- 원본 비율을 유지한 크기 조절
- 상품이 잘리지 않는 `contain` 배치
- 안전 영역을 고려한 제한적 `cover` 크롭
- 단색, 그라데이션, 패턴 배경 추가
- CSS 기반 그림자와 광원 효과
- 모서리, 프레임, 마스크 적용
- 명도, 대비, 채도의 경미한 보정
- 동일 사진을 다른 비율로 파생
- 사진 위에 HTML 텍스트와 SVG 장식 배치

### 7.2 금지되는 처리

- 상품의 가로세로 비율 왜곡
- 제품 색상 임의 변경
- 로고나 라벨 제거 또는 변형
- 실제로 없는 버튼, 구성품, 기능 추가
- 상품의 중요한 부분을 가리는 텍스트 배치
- 낮은 해상도 이미지를 과도하게 확대

### 7.3 사진이 부족한 경우

우선순위는 다음과 같다.

1. 동일한 실제 상품 사진을 다른 안전한 레이아웃으로 재사용
2. 사진 없이 완성 가능한 HTML/CSS 정보 그래픽으로 전환
3. 판매자가 추가로 촬영해야 할 사진을 체크리스트로 안내
4. 필수 섹션이 아니라면 결과에서 제외

## 8. 기본 상세페이지 섹션

### 8.1 HERO

- 실제 대표 상품 사진
- 브랜드 팔레트 배경
- 확인된 핵심 가치 한 문장
- 최대 3개의 짧은 정보 배지
- 상품을 가리지 않는 텍스트 안전 영역

### 8.2 고객 문제

- 사진이 적합하면 실제 사용 장면 사용
- 사진이 없으면 아이콘과 짧은 문제 카드로 구성
- 과도한 공포나 근거 없는 문제 표현 금지

### 8.3 핵심 장점

- 3~5개의 HTML/CSS 카드
- 확인된 수치만 강조
- SVG 아이콘, 숫자, 짧은 설명 사용
- 실제 상품 디테일 사진이 있으면 카드와 함께 배치

### 8.4 사용 방법 또는 사용 장면

- 실제 사용 사진이 있을 때만 사진형 섹션 사용
- 없으면 단계형 안내 그래픽으로 전환
- 상품별 사용 순서가 확인되지 않으면 생성하지 않음

### 8.5 스펙과 구성품

- HTML/CSS 표 또는 구성품 카드
- 값마다 확인 상태와 출처 연결
- 미확인 값은 판매용 결과에서 제외

### 8.6 구매 전 확인과 CTA

- 배송, 보증, 주의사항 등 확인된 정보
- 상품 사진을 반복 사용하지 않아도 완성 가능한 텍스트 중심 구조
- 판매처 정책을 발명하지 않음

## 9. 템플릿 시스템

첫 단계에서는 세 가지 템플릿만 제공한다.

| 템플릿 | 적합한 상품 | 특징 |
| --- | --- | --- |
| `clean_product` | 생활용품, 소형 가전 | 밝은 배경, 큰 상품 사진, 명확한 스펙 |
| `benefit_cards` | 기능이 많은 제품 | 수치와 장점 카드 중심 |
| `editorial_story` | 패션, 뷰티, 감성 상품 | 큰 사진, 여백, 짧은 문구 중심 |

템플릿은 색상만 바꾸는 스킨이 아니라 섹션 순서, 이미지 비율, 텍스트 밀도와 레이아웃 규칙을
포함한다.

## 10. 데이터 계약

원본 이미지와 파생 이미지를 구분한다.

```json
{
  "asset_id": "asset-123",
  "source_type": "upload",
  "role": "product_main",
  "original_asset_id": null,
  "width": 1600,
  "height": 1600,
  "quality_status": "usable",
  "identity_status": "confirmed",
  "transform": null
}
```

파생 자산은 원본과 변환 명세를 가진다.

```json
{
  "asset_id": "asset-derived-456",
  "source_type": "composed",
  "role": "hero",
  "original_asset_id": "asset-123",
  "transform": {
    "fit": "contain",
    "position": "center",
    "background": "linear-gradient(135deg, #F7FAF8, #E8F5EE)",
    "shadow": "soft",
    "aspect_ratio": "4:3"
  }
}
```

섹션은 이미지와 HTML/CSS 디자인 명세를 함께 가진다.

```json
{
  "visual_kind": "composed_product | html_graphic",
  "image_asset_id": "asset-123",
  "visual_payload": {
    "layout_variant": "hero_product_right",
    "product_fit": "contain",
    "text_safe_area": "left",
    "background_token": "surface_mint",
    "decoration_tokens": ["soft_circle", "accent_line"],
    "badges": ["확인된 핵심 정보"]
  }
}
```

## 11. 편집 경험

판매자는 결과 화면에서 다음 작업을 할 수 있다.

- 섹션별 사용 사진 교체
- 상품 사진의 확대, 축소와 위치 조정
- 배경색 또는 브랜드 팔레트 변경
- 제목과 본문 직접 수정
- 장점 카드 순서 변경
- 아이콘 교체
- 섹션 숨기기와 순서 변경
- 자동 조합으로 되돌리기

편집기는 상품 원본을 직접 수정하지 않고 레이아웃과 변환 설정만 저장한다.

## 12. 오류 및 대체 UX

빨간색 Mock 이미지는 사용자 화면에서 제거한다.

| 상황 | 사용자 화면 처리 |
| --- | --- |
| 대표 사진 없음 | 사진 업로드 요청과 촬영 가이드 표시 |
| 사진 해상도 부족 | 경고 표시 후 교체 권장 |
| 사용 장면 없음 | 단계형 HTML 그래픽으로 자동 전환 |
| 구성품 정보 미확인 | 해당 카드 제외 및 확인 요청 |
| 이미지 로딩 실패 | export 차단 및 실패 자산 표시 |
| Playwright 미설치 | 설치 방법을 포함한 운영 오류 반환 |

개발용 상태와 사용자용 결과를 분리하고 `ai_generated` 같은 내부 표식을 최종 상세페이지에
노출하지 않는다.

## 13. PNG/JPG 출력

- 미리보기와 export가 동일한 `DetailPageDocument`를 사용한다.
- 모든 상품 이미지의 로딩 완료 후에만 캡처한다.
- 폰트, SVG, 배경과 그림자가 최종 이미지에 포함되어야 한다.
- JPG는 흰색 배경으로 합성하며 품질 설정을 적용한다.
- PNG는 투명 배경이 필요한 개별 자산에만 허용하고 상세페이지 기본 출력은 불투명 배경을 쓴다.
- 이미지 누락 또는 로딩 실패가 있으면 성공 파일을 가장하지 않고 export를 차단한다.
- 다운로드 결과와 화면 미리보기의 주요 레이아웃 차이가 없어야 한다.

## 14. 구현 단계

### 14.0 스프린트 운영 원칙

- 기본 단위는 1주 스프린트로 한다.
- 각 스프린트는 독립적으로 시연 가능한 사용자 결과를 남긴다.
- 기준 상품은 소형 가전, 뷰티, 생활용품 각 1종으로 고정한다.
- 새로운 기능보다 미리보기와 다운로드 결과의 일치를 우선한다.
- 외부 이미지 API 없이 통과해야 하는 기본 품질 기준과 선택적 API 품질 기준을 분리한다.
- 스프린트 종료 시 테스트 로그, 실제 JPG 결과와 남은 문제를 문서화한다.

### Sprint 0: 기준선 확보와 JPG 출력 복구

목표: 현재 상태를 재현하고 이후 개선을 비교할 수 있는 기준 결과를 만든다.

작업:

- Playwright Chromium 설치와 실행 전 점검
- PNG/JPG 다운로드 실패 원인과 오류 메시지 정리
- 기준 상품 3종의 현재 Mock 결과 저장
- 미리보기와 다운로드 결과의 차이 기록
- 빨간 Mock 이미지, 누락 이미지, 내부 배지 노출 위치 목록화

완료 조건:

- 기준 상품 최소 1종을 JPG로 정상 다운로드한다.
- 현재 품질 문제를 스크린샷과 체크리스트로 재현할 수 있다.
- 다음 스프린트가 비교할 기준 파일을 확보한다.

### Sprint 1: 실제 상품 이미지 우선 연결

목표: 빨간 Mock 이미지 대신 사용자가 제공한 실제 상품 사진을 결과에 표시한다.

작업:

- 업로드 이미지와 URL 수집 이미지의 저장 경로 점검
- 대표 상품 사진 선택 규칙 구현
- HERO와 상품 소개 섹션에 실제 이미지 자동 연결
- 원본 이미지 보존과 파생 자산 관계 저장
- `ai_generated` 등 내부 개발 표식 제거
- 실제 사진이 있으면 Mock 이미지 생성을 건너뛰는 정책 적용

완료 조건:

- 실제 상품 사진이 HERO에 표시된다.
- 빨간 사각형이 최종 미리보기와 다운로드에 나오지 않는다.
- 상품 사진의 비율과 색상이 변하지 않는다.

### Sprint 2: 이미지 자산 분류와 품질 검사

목표: 수집된 사진을 상세페이지에서 안전하게 재사용할 수 있도록 정리한다.

작업:

- `product_main`, `product_detail`, `usage_scene`, `components` 역할 도입
- 해상도, 비율, 중복과 잘림 가능성 검사
- 대표 이미지 선택 및 역할 변경 UI
- 섹션별 사용 이미지 확인 UI
- 저해상도 및 부적합 이미지 경고

완료 조건:

- 판매자가 이미지 역할과 사용 위치를 확인하고 바꿀 수 있다.
- 저품질 이미지를 자동으로 HERO에 사용하지 않는다.
- 같은 이미지의 불필요한 반복을 줄인다.

### Sprint 3: HERO 비주얼 자동 조합 MVP

목표: 실제 상품 사진 한 장으로 완성도 있는 첫 화면을 만든다.

작업:

- `contain` 중심의 상품 배치 엔진
- 단색과 그라데이션 배경 토큰
- CSS 그림자, 강조 원, 장식선과 SVG 요소
- 상품 위치에 따른 텍스트 안전 영역 계산
- 제목, 본문과 정보 배지를 HTML로 렌더링
- `clean_product` HERO 레이아웃 구현

완료 조건:

- 이미지 API 없이 상품 중심 HERO가 완성된다.
- 상품과 텍스트가 겹치지 않는다.
- 모바일 폭과 export 폭에서 레이아웃이 유지된다.

### Sprint 4: 핵심 섹션 HTML/CSS 그래픽

목표: 추가 사진이 부족해도 상세페이지 주요 내용을 완성한다.

작업:

- 핵심 장점 카드
- 확인된 수치 강조 블록
- 사용 단계 그래픽
- 스펙 표와 구성품 카드
- 구매 전 확인과 CTA 블록
- 사진 부족 시 HTML 그래픽으로 전환하는 결정 규칙
- `benefit_cards` 템플릿 구현

완료 조건:

- 사진이 한 장뿐인 상품도 빈 섹션 없이 결과를 만든다.
- 확인되지 않은 수치와 구성품을 표시하지 않는다.
- 이미지가 없는 HTML 그래픽을 누락 이미지로 판정하지 않는다.

### Sprint 5: 템플릿과 판매자 편집

목표: 자동 결과를 판매자가 짧은 시간 안에 원하는 방향으로 다듬게 한다.

작업:

- `clean_product`, `benefit_cards`, `editorial_story` 템플릿 제공
- 섹션별 사진 교체
- 상품 확대, 축소와 위치 조정
- 배경과 브랜드 팔레트 변경
- 카드 순서, 아이콘과 섹션 순서 변경
- 자동 조합으로 되돌리기

완료 조건:

- 판매자가 코드 수정 없이 주요 비주얼을 편집한다.
- 편집이 원본 상품 사진을 변경하지 않는다.
- 변경 내용이 저장 후 다시 열어도 유지된다.

### Sprint 6: 미리보기와 PNG/JPG 출력 일치

목표: 화면에서 확인한 결과를 그대로 다운로드한다.

작업:

- 미리보기와 export의 canonical renderer 통합
- 폰트, 이미지와 SVG 로딩 완료 신호
- JPG 배경과 품질 옵션
- 이미지 로딩 실패 시 export 차단
- 편집용 UI와 내부 배지 출력 제외
- 주요 레이아웃 시각 회귀 테스트

완료 조건:

- 미리보기와 JPG의 주요 배치가 일치한다.
- 빨간 Mock 이미지와 편집용 UI가 출력되지 않는다.
- 실패한 다운로드를 성공으로 기록하지 않는다.

### Sprint 7: 기준 상품 3종 품질 검증

목표: 특정 상품에만 맞춘 구현이 아닌지 검증하고 기본 기능을 안정화한다.

작업:

- 소형 가전, 뷰티, 생활용품 실사용 생성
- 상품 정체성, 사실성, 가독성과 이미지 품질 검수
- 수정 횟수와 생성 시간 측정
- 발견된 공통 문제 우선 수정
- 업로드 파일 규격과 다운로드 안정성 확인

완료 조건:

- 기준 상품 3종 모두 JPG 결과를 생성한다.
- 상품 정체성 훼손과 근거 없는 표현이 없다.
- 상품별 이미지 교체 2회 이하, 문구 수정 5회 이하로 업로드 준비 상태에 도달한다.

### Sprint 8: 선택적 GPT 이미지 보강 실험

목표: 기본 경로를 대체하지 않고, 실제로 가치가 있는 구간에만 GPT 이미지 API를 적용할지
결정한다.

작업:

- 동일 상품과 동일 레이아웃으로 API 미사용 결과와 GPT 이미지 결과 비교
- 실제 상품 사진을 입력으로 사용하는 편집 방식 검증
- 배경 확장, 분위기 연출과 보조 장면 후보 생성
- 상품 외형, 로고, 색상과 구성품 보존 검사
- 이미지당 비용, 생성 시간, 실패와 재시도율 기록
- 판매자가 API 사용 여부를 명시적으로 선택하는 UX 검토

완료 조건:

- 품질 향상이 비용과 정체성 위험보다 큰 사용 사례를 정의한다.
- API 실패 시 기본 자동 조합 결과로 안전하게 되돌아간다.
- GPT 이미지 기능을 기본값, 유료 옵션 또는 제외 중 하나로 결정한다.

### 스프린트 의존 관계

```text
Sprint 0 출력 복구
    ↓
Sprint 1 실제 이미지 연결
    ↓
Sprint 2 자산 분류
    ↓
Sprint 3 HERO 조합
    ↓
Sprint 4 상세 섹션 그래픽
    ↓
Sprint 5 편집
    ↓
Sprint 6 출력 일치
    ↓
Sprint 7 품질 검증
    ↓
Sprint 8 선택적 GPT 이미지 실험
```

Sprint 0~7이 이미지 API 없는 기본 제품의 필수 범위다. Sprint 8은 기본 품질 기준을 통과한
뒤 진행하는 선택 범위이며, 앞선 스프린트의 완료를 막지 않는다.

## 15. 인수 기준

다음 조건을 모두 만족하면 이번 기획을 완료한 것으로 본다.

1. Mock 모드에서도 빨간 사각형이나 내부 개발 표식이 사용자 결과에 나오지 않는다.
2. 실제 상품 사진이 HERO와 적합한 상세 섹션에 자동 배치된다.
3. 상품 사진의 비율, 색상, 로고와 형태가 임의로 변하지 않는다.
4. 사진이 없는 섹션은 완성된 HTML/CSS 그래픽 또는 명확한 입력 요청으로 대체된다.
5. 확인되지 않은 수치나 구성품을 시각 요소로 발명하지 않는다.
6. 판매자가 섹션별 사진과 배치를 수정할 수 있다.
7. JPG/PNG 다운로드에 빨간 Mock 이미지와 편집용 UI가 포함되지 않는다.
8. 미리보기와 다운로드 결과가 동일한 렌더러를 사용한다.
9. 외부 이미지 생성 API 키가 없어도 전체 생성 흐름을 완료할 수 있다.
10. 기준 상품 3종에서 업로드 가능한 상세페이지 결과를 얻는다.

## 16. 성공 지표

- 상세페이지 생성 성공률
- 이미지 누락으로 인한 export 차단 비율
- 생성 후 판매자가 교체한 이미지 수
- 생성 후 판매자가 수정한 섹션 수
- 첫 생성부터 JPG 다운로드까지 걸린 시간
- 상품 정보 오류 또는 상품 정체성 훼손 건수
- 기준 상품별 업로드 준비 완료율

초기 목표는 기준 상품 3종에서 이미지 누락 없이 결과를 생성하고, 각 상품당 이미지 교체
2회 이하와 문구 수정 5회 이하로 업로드 준비 상태에 도달하는 것이다.

## 17. 향후 확장

이번 조합 엔진은 상세페이지 품질이 안정된 뒤 다음 출력에 재사용한다.

- 인스타그램 카드뉴스 1:1 및 4:5
- 숏폼 세로형 장면 카드 9:16
- 마켓플레이스 썸네일
- 광고 배너
- 브랜드별 템플릿 묶음

상품 분석과 실제 이미지 자산을 공통으로 사용하고 출력 비율과 레이아웃만 변경한다. 카드뉴스와
숏폼 확장은 본 문서의 인수 기준을 통과한 뒤 별도 기획과 구현으로 시작한다.

## 18. 결정 사항

- 상세페이지 품질 개선을 카드뉴스와 숏폼보다 먼저 진행한다.
- 외부 이미지 생성 API는 필수 의존성에서 제외한다.
- 실제 상품 사진과 HTML/CSS/SVG 조합을 기본 비주얼 전략으로 사용한다.
- 생성형 이미지가 없다는 이유로 빨간색 또는 빈 플레이스홀더를 최종 결과에 표시하지 않는다.
- 구현은 출력 안정화, 자산 관리, 자동 조합, 편집·출력 일치, 품질 검증 순서로 진행한다.
