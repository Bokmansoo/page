# Sellform V2.1 LG-7 브라우저 검증 가이드

## 1. 준비

1. 백엔드를 재시작하고 `http://localhost:8001/`에서 `{"status":"running","service":"Sellform Core API"}`가 보이는지 확인한다.
2. `.env`는 mock/fake 모드를 유지한다. 실제 유료 이미지·LLM API는 사용하지 않는다.
3. 프런트엔드는 `http://localhost:3000/workspace`로 연다.
4. 기존 실행은 호환성을 위해 전문가 모드로 보일 수 있으므로 LG-7 검증은 새 상품으로 시작하는 것이 가장 명확하다.

## 2. 새 실행과 모드 확인

1. `AI 상세페이지 생성`에서 상품 정보를 입력한다.
2. 기본 선택이 **빠른 생성(권장)**인지 확인한다.
3. 생성 후 주소가 다음 형태인지 확인한다.
   `http://localhost:3000/workspace/projects/{project_id}/planning?runId={run_id}`
4. 기획 화면 상단의 **Creative Brief 입력 · 생성 모드** 패널을 찾는다.
5. **전문가 검수**를 누르고 새로고침한다. 전문가 검수가 계속 선택되어야 한다.
6. 다시 **빠른 생성**을 누르고 새로고침한다. 기존 입력·산출물이 사라지지 않아야 한다.

## 3. 리뷰 전용 입력 확인

직접 붙여넣기에 다음 예시를 사용한다.

```text
출퇴근 때 가볍고 조용해서 만족합니다.
손잡이는 불편합니다.
배터리가 10시간 간다는 후기가 반복됩니다.
여행 중 휴대하기 좋다는 의견이 많습니다.
```

1. 출처를 `seller_paste`로 둔다.
2. 동의 여부와 권리 상태를 선택한다.
3. **분석 저장**을 누른다.
4. 리뷰 수가 1 증가하고 불만·구매 이유·반복 표현·추정 타깃 요약이 보여야 한다.
5. `배터리 10시간`은 리뷰 주장일 뿐 승인 사실이 아니므로 **사실 승격 차단** 상태여야 한다.
6. 같은 방법으로 `.csv`, `.xlsx`, `.txt` 파일도 각각 저장할 수 있어야 한다.

## 4. 레퍼런스 전용 입력 확인

1. 종류를 `URL`로 선택하고 `https://example.com/reference-detail`을 입력한다.
2. 사용할 신호는 **레이아웃**과 **섹션 흐름**만 선택한다.
3. 권리 상태는 `미확인`으로 둔 뒤 **추상 신호 저장**을 누른다.
4. 결과는 **분석 전용(analysis_only)**으로 보여야 한다.
5. 저장된 신호에는 layout/section flow만 있고 원문 카피·로고·상품 이미지·고유 디자인 복제 정보가 없어야 한다.
6. 이미지/PDF를 시험할 때는 먼저 프로젝트에 파일을 업로드하고 화면의 파일명 목록에서 선택한다. raw asset ID를 직접 입력하는 칸은 없어야 한다.

## 5. 판매자 창작 방향 확인

다음 값을 입력하고 **방향 저장**을 누른다.

- 타깃: `출퇴근·여행 중 휴대성과 간편함을 중시하는 사용자`
- 원하는 분위기: `깔끔함, 신뢰감, 프리미엄`
- 강조점: `휴대성, 사용 편의, 정돈된 정보 구조`
- 금지 장면/표현: `의료 효능 연출, 공급처 로고, 과장된 성능 비교, 가격 복제`

저장 후 새로고침해도 네 항목이 유지되어야 한다. 사실 검증 결과 때문에 이 창작 방향이 삭제되거나 덮어써지면 안 된다.

## 6. 그래프 진행과 Creative Brief 확인

1. 현재 판매자 승인 카드의 **확인·다음 단계**를 진행한다.
2. quick 모드에서는 안전한 일반 승인만 자동 처리될 수 있다.
3. 사실 충돌, 비용, 권리, 제품 정체성, 정책 위험은 quick 모드에서도 반드시 멈춰야 한다.
4. `creative_brief_compiler`가 `sales_strategy`보다 먼저 실행되어야 한다.
5. 프로젝트 인텔리전스 조회에서 새 Product Creative Brief의 version/hash, 이전 version ID, fact snapshot, prompt pack, Brand Kit, review/reference insight ID가 보여야 한다.
6. 브리프 입력을 변경해 새 버전을 만들면 source collection과 승인 사실은 유지되고 sales/page/copy/visual 이후 산출물만 stale 처리되어야 한다.

## 7. 기대 결과 체크리스트

- [ ] 리뷰와 레퍼런스가 서로 다른 입력 영역과 API로 저장된다.
- [ ] 리뷰 claim은 승인 사실로 자동 승격되지 않는다.
- [ ] 권리 미확인 레퍼런스는 최종 이미지가 아니라 분석 전용이다.
- [ ] 판매자 mood/target/emphasis/forbidden scene이 새로고침 후 유지된다.
- [ ] quick/expert 전환 후 기존 산출물과 승인이 보존된다.
- [ ] quick도 비용·권리·정체성·정책 gate를 건너뛰지 않는다.
- [ ] 브리프의 pack/Brand Kit/fact snapshot 버전과 hash가 고정된다.
- [ ] 화면에 `[object Object]`가 표시되지 않는다.

위 항목이 모두 맞으면 LG-7 사용자 검증은 완료이며 LG-8로 진행할 수 있다.
