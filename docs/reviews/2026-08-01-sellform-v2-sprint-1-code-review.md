# Sellform V2 Sprint 1 코드리뷰 — 상품 자료 묶음 입력

검토일: 2026-08-01  
대상 기획: `docs/superpowers/plans/2026-08-01-sellform-v2-sprint-1-product-input-bundle.md`  
최종 결론: **재검토 중 발견된 누락을 보완했으며 Sprint 1 완료 조건 충족**

## 1. 재검토에서 발견한 문제

최초 코드리뷰의 완료 판단 이후 기획서와 코드를 다시 대조해 다음 누락을 확인했다.

1. 필수 최소 입력이 프런트엔드에서만 검사되어 API를 직접 호출하면 대표 사진이나 판매자 핵심 정보 없이 입력 묶음을 확정할 수 있었다.
2. 사진 순서는 JSON 스냅샷에만 있고 개별 `Asset`에는 저장되지 않았다.
3. URL 수집 결과 조회 API는 있었지만 기획 화면에서는 정확한 상태와 실패 원인을 표시하지 않았다.
4. 기획 화면의 기존 한글 문구 일부가 깨진 상태였다.
5. 실제 업로드 API에서 허용하는 출처 값을 세 가지 권리 선택으로 제한하지 않아 임의 출처 값을 전달할 수 있었다.
6. 기존 회귀 테스트 일부가 V2의 `reference_only` 정책과 `seller_confirmed` 상태를 반영하지 못했다.
7. `42°C`, 권리 선택, 최소 입력, URL 중복 병합을 브라우저·API 계약 수준에서 충분히 검증하지 않았다.

위 항목은 이번 재검토에서 모두 수정했다.

## 3. 주요 데이터·API 계약

- `ProductProject.intake_snapshot.input_bundle`
  - 상품명, 카테고리, 설명, 기능, 구성품, 주의사항
  - 가격, 배송, 판매 채널, 모델·옵션
  - 상품/참고 URL, 자산 ID, 자산 메타데이터, 수집 시도 상태
- `Asset.intake_order`
  - 판매자가 확정한 사진 순서를 1부터 저장한다.
- `SourceCapture`
  - URL, 플랫폼, 상품/참고 역할, 수집 상태, 실패 코드, 수집 개수, 시각을 보존한다.
- `PATCH /api/agent-runs/{run_id}/input-assets`
  - 프로젝트 소유권과 최소 입력을 검증하고 입력 묶음을 한 번만 확정한다.
- `GET /api/v1/projects/{project_id}/source-captures`
  - 현재 워크스페이스에 속한 URL 수집 기록만 반환한다.

## 4. 자동 검증 결과

### 4.1 백엔드

다음 Sprint 1 및 인접 회귀 테스트를 한 번에 실행했다.

```text
37 passed
```

검증 범위:

- V2 Sprint 1 입력 계약
- 기존 상품 자료 묶음 흐름
- 판매자 숫자·단위 사실 저장
- 런타임 스키마 호환성
- 실제 상품 이미지 흐름
- 프로젝트 자산 API
- Agent Run API

### 4.2 프런트엔드

```text
npm.cmd run build
Compiled successfully
TypeScript 검사 성공
```

### 4.3 브라우저 흐름

Playwright 테스트의 세 시나리오가 각각 통과했다.

1. 사진 5장 업로드 및 순서 변경
2. `260g`, `10분`, `800mAh`, `42°C` 검토 화면 보존
3. 판매 채널, 모델·옵션, 사진 순서, 공급처 참고 권리 표시

테스트 자체는 3건 모두 `ok`였으나, 샌드박스가 Google Fonts 외부 요청을 차단하면서 개발 서버 종료가 지연되어 전체 명령은 제한 시간에 종료됐다. 애플리케이션 빌드와 테스트 assertion 실패는 없었다.

## 5. 범위 제외 확인

- 이미지 역할 분류와 OCR 분석은 Sprint 2에서 처리한다.
- 403·로그인·캡차를 우회하지 않는다.
- 공급처 자료의 최종 사용 권리는 자동 승인하지 않는다.
- 브라우저 확장 프로그램 자체는 Sprint 8에서 구현한다.
- 서로 다른 URL과 로컬 파일의 픽셀 단위 유사 이미지 판별은 Sprint 2 자산 이해 범위다. Sprint 1에서는 동일 URL과 동일 자산 ID 중복을 제거한다.

## 6. 최종 판단

입력 이미지의 출처, 권리 상태, 사진 순서, 프로젝트 소유권, URL 수집 상태, 판매자 숫자·단위가 모두 보존되고 서버에서 검증된다. 따라서 Sprint 1 기획의 완료 기준과 Sprint 2 진입 조건을 충족한다.
