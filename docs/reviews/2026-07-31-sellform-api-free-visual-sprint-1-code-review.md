> 2026-08-01 보완: URL 수집 이미지는 후보로만 제공하고, 사용자가 `이 URL 이미지 승인`을 선택한 뒤에만 페이지 섹션에 연결하도록 수정했다. 여러 URL 이미지 중 `main`·`front`·`대표`·`정면` 파일명을 우선 후보로 정렬하는 테스트와 URL 선택 API 통합 테스트를 추가했다.

## 1. 결론

Sprint 1의 핵심 정책인 `업로드 > URL 수집 이미지 > 사진 필요 상태`가 구현됐다. Mock 모드에서
실제 사진이 있으면 이미지 생성기를 호출하지 않고 기존 `Asset`의 ID를 HERO와 상품 소개용
섹션에 직접 연결한다. 사진이 없을 때는 빨간 Mock 자산을 만들지 않고 `missing-image` 상태와
`상품 사진을 추가해 주세요` 안내를 반환한다.

기존 빨간 Mock 자산 ID도 최종 상세페이지에서는 이미지로 렌더링하지 않는다. 이미지 후보 패널은
직접 업로드와 URL 추출을 사람이 읽을 수 있는 출처명으로 표시하며, 내부 `ai_generated` 문구는
최종 결과와 export 문서에 표시되지 않는다.

## 3. 변경 요약

- URL 수집 이미지가 프로젝트 Asset으로 저장돼 페이지 섹션·후보·향후 메타데이터 작업에서 같은
  ID를 공유한다.
- 실제 사진이 한 장이면 HERO와 필요한 후속 섹션에서 그 원본 ID를 재사용한다. 두 장 이상이면
  첫 사진은 HERO, 두 번째 사진은 상품 소개 섹션에 우선 연결한다.
- Mock 모드에는 더 이상 가짜 상품 이미지 Asset을 만들지 않는다.
- 사진이 없으면 최종 화면과 후보 패널에 사진 추가 안내를 표시한다.
- 사진 파일은 `object-contain`으로 렌더링해 강제 크롭으로 인한 로고·비율 손상을 피한다.

## 2026-08-01 재검토 및 보완 결과

- URL 이미지는 자동으로 HERO에 적용되지 않는다. 후보 패널에서 `이 URL 이미지 승인`을 누르면 해당 원본 Asset ID가 섹션에 저장된다.
- 업로드 이미지가 있으면 업로드 이미지가 여전히 자동 우선 적용된다. URL로 작업을 시작한 뒤 업로드한 사진도 HERO 우선순위를 가진다.
- URL 이미지 여러 장, URL 선택 전 누락 상태, URL 선택 후 HERO 연결을 테스트로 검증했다.
- Sprint 1 관련 전체 회귀 테스트 결과: `30 passed`. URL 승인 후 임시 누락 상태 제거와 페이지 수정 API까지 포함한 추가 검증 결과: `24 passed`.
- 프론트엔드 `npm.cmd run lint` 결과: 오류 없음. 기존 React Hook 및 `<img>` 권고 경고만 남아 있다.

실제 판매 상품 사진을 사용한 최종 JPG의 시각적 확인은 자동 테스트만으로 대체할 수 없으므로, 서버에서 한 번 생성·다운로드하여 최종 확인한다.
